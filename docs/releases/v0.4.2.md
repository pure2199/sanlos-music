# Sanlos Music v0.4.2 —— 发布说明

> 相对 **v0.4.1** 的一次**改名**：**里层代号全部换成 `sanlos`**——
> 包名、appId、内部协议、工具脚本、仓库默认分支。
>
> **界面一个字没变**（软件名仍是「Sanlos Music」），**功能零变化**——
> 这一版只是把「代码里的旧代号」收拾干净，让它和**你看到的名字**一致。
>
> ⚠ **唯一要动手的一步**：这一版的 **appId 变了** ⇒ **不是原地升级**
> ⇒ **先在「已安装的应用」里卸载旧版，再装新版**。
> （**登录态、播放历史、续播位置都不会丢** —— 见第五节。）
>
> 这一版的产物**仍然没有代码签名** ⇒ 替代信任锚是 **GitHub 构建来源证明**（artifact attestation）。

发布日期：**2026-11-19**

## 一、这一版改了什么

| 改的东西 | 之前（v0.4.1） | 现在（v0.4.2） | 你要做什么 |
|---|---|---|---|
| 软件名（界面 / 快捷方式 / 窗口标题） | Sanlos Music | **不变** | 不用管 |
| 安装包文件名 | `SanlosMusic-Setup-0.4.1.exe` | **`SanlosMusic-Setup-0.4.2.exe`** | 下新的那个 |
| appId（决定卸载项 GUID） | `com.fnmusic.desktop` | **`com.sanlos.music`** | ⚠ **卸载旧版再装** |
| 内部协议（应用自己用） | `fnm://` / `fnml://` | **`sanlos://` / `sanlos-media://`** | 不用管（见第二节 3） |
| npm 包名 | `fnmusic-desktop` | **`sanlos-music`** | 只影响自己 `npm install` 过这个包的人 |
| 仓库默认分支 | `feature/fnmusic-desktop` | **`sanlos-music`** | ⚠ **clone 地址变了**（旧分支已不存在） |
| 仓库里的工具脚本 | `tools/fn-*.mjs` | **`tools/sanlos-*.mjs`** | 只影响跑脚本的人 |

⚠ **这一版没有任何功能改动** ⇒ v0.4.1 的每一个功能、每一个界面，都**原样保留**。

## 二、⚠ 已知影响（如实标注）

### 1. 这一版**不是原地升级**（因为 appId 变了）

electron-builder 用 `appId` 推导**卸载项的 GUID** ⇒ appId 一变，GUID 就变
⇒ 装完新版之后，**「已安装的应用」里会同时出现两条**：
一条旧的（v0.4.1）、一条新的（v0.4.2）。

⇒ **正确做法**：装新版**之前**先卸载旧版。

| | 说明 |
|---|---|
| 卸载旧版会删什么 | 只删安装目录（默认 `D:\Sanlos Music`） |
| 卸载旧版**不会**删什么 | **登录态、播放历史、续播位置、设置**（它们在 `%APPDATA%\Sanlos Music` 里，**不在安装目录**） |
| 怎么卸载 | 「已安装的应用」→ 找到 **Sanlos Music 0.4.1** → 卸载 → 再装 v0.4.2 |

⚠ **如果你不卸载直接装** ⇒ 两条卸载项都指向同一个目录
⇒ 将来从**旧的那条**卸载，**会连 v0.4.2 一起删掉**。

### 2. **登录态 / 播放历史 / 续播位置都不会丢**

| 东西 | 为什么丢不了 |
|---|---|
| **登录态** | 软件名仍是 `Sanlos Music` ⇒ **用户数据目录名一个字没变** ⇒ 重新装上还是已登录 |
| **播放历史 / 续播位置 / 按歌指定歌词源** | 这三个本机记录的**旧键名**被保留成了「回落键」⇒ 新键没有时**自动去读旧键**（只读、不删）⇒ 老记录**照常在** |

⚠ **但有第四个本机记录**（「有声」页那次**全库扫描**的结果：哪些专辑被自动判定成有声读物、
你手工改判过哪些）**没跟上改名** ⇒ v0.4.2 **读不到**它
⇒ 后果：**有声读物的自动判定失效**（「有声读物被误配桌面歌词」那条老毛病会回来），
你在「有声」页的手工改判也丢 ⇒ 「有声」页下次进入会**自动重扫一次**（实测 87 页 / 6–47 分钟）。

⇒ **已定位、已记为 T117**（补旧键回落 ＋ 钉测试 ＋ 发 v0.4.3）。
**除这一项外，这一版不丢任何东西。**

### 3. 旧协议名**不再注册**

应用内部的自定义协议从 `fnm://` / `fnml://` 换成了 `sanlos://` / `sanlos-media://`。
**你自己用不到**（那是应用和它自己的主进程之间说话用的）。

⚠ **唯一的例外**：如果**你自己写的脚本 / 自动化工具**直接调过 `fnm://` 或 `fnml://`
⇒ 那些调用**要改成新协议名**。

### 4. 仓库默认分支改名 ⇒ **clone 地址变了**

```
# 旧地址（分支已不存在）
git clone --branch feature/fnmusic-desktop git@github.com:pure2199/sanlos-music.git
# 新地址
git clone git@github.com:pure2199/sanlos-music.git
```

⚠ **历史版本一个都没丢** ⇒ 所有旧 tag（`v0.1.0` … `v0.4.1`）**照旧可下载**。

### 5. 飞牛 NAS 侧**一个字都没动**

`fnos` / `fnId` / `FN_USER` / `FN_PASS` / `FN_ID` / 接口返回的 `fn: [...]` 数组字段
—— 这些是**飞牛那边的名字**，不是本客户端的 ⇒ **全部原样保留**
⇒ **与 NAS 的连通性不受影响**。

## 四、这一版的产物**仍然没有代码签名**

| 项 | 状态 |
|---|---|
| 代码签名 | ❌ **没有** ⇒ Windows 可能提示「未知发布者」⇒ **蓝框怎么绕**见 [README 的下载说明](../README.md) |
| 构建来源证明 | ✅ **有**（GitHub artifact attestation / SLSA provenance）⇒ 证明每个产物确实是**本仓库的 CI** 从对应标签构建出来的，**换一字节就验不过** |

⚠ **为什么还是没签名**：SignPath Foundation 的免费签名申请**已被拒**
（2026-11-12，原因是**可见度不足**，不是代码质量）
⇒ 全球范围内对个人/小团队而言，「**公开可信的代码签名证书**」目前只剩**付费**一条路。

⚠ **SmartScreen 蓝框可以绕**（不是「无法绕过」）：

1. 右键安装包 → **属性** → 底部勾「**解除锁定**」→ 应用 ⇒ **蓝框直接消失**；
2. 或者用**应用内的一键更新**下载 —— 应用自己下载的包**不带「来自互联网」标记** ⇒ 安装时不弹蓝框。

⚠ 但 **Smart App Control（Windows 11 的「应用控制」）是硬拦** —— 那条路未签名绕不过。

## 六、这一版的校验值

⚠ NSIS 安装器**内嵌构建时间戳** ⇒ **两次构建的字节必然不同**
⇒ 校验值**只能逐版本给**，且只对**本 Release 页面**里那几个资产有效。

⇒ 逐字比对 **Release 页面末尾「下载校验（sha256）」** 那张表即可
（也可以用 `gh attestation verify "SanlosMusic-Setup-0.4.2.exe" --repo pure2199/sanlos-music` 验构建来源）。

这一版的三个产物（文件名与软件名一致，**不带空格**）：

| 文件 | 说明 |
|---|---|
| `SanlosMusic-Setup-0.4.2.exe` | **安装版**（NSIS，可改安装目录） |
| `SanlosMusic-Portable-0.4.2.exe` | **便携版**（免安装，双击即用） |
| `latest.json` | **自动更新清单**（自动更新走它 ⇒ Release 必须是 latest） |
