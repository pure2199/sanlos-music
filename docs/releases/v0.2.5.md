# Sanlos Music v0.2.5 —— 发布说明

> 相对 **v0.2.4** 的一次更新：**把「公开产物的代码签名」这条链路整体做完并搬进 CI**，
> 但**这一版的产物仍然没有签名** —— 免费签名申请**已提交、审核中** ⇒
> **下一个版本（v0.2.6）起**才会真正带上签名。

发布日期：**2026-11-11**

---

## 一、这一版改了什么

### 1. 产物仍未签名，但**多了三条零成本的绕法**

这一版**没有**代码签名 ⇒ Windows SmartScreen 照旧会拦（蓝色「Windows 已保护你的电脑」）。
现在文档给了**三条绕法**，任选其一：

| 办法 | 怎么做 | 效果 |
|---|---|---|
| **① 点「更多信息」→「仍要运行」** | 蓝框里那个小字链接 | 传统的绕法，**要两步** |
| **② 勾「解除锁定」（推荐）** | 右键安装包 → **属性** → 底部勾「**解除锁定**」→ 应用 | **蓝框直接消失**，以后也不拦 |
| **③ 命令行一次搞定** | PowerShell：`Unblock-File .\FN-Music-Setup-0.2.5.exe` | 同 ②，适合批量 |

> ℹ️ **为什么勾「解除锁定」就行**：Windows 的 SmartScreen 下载拦截，是**因为文件带「来自互联网」标记**
> （Mark of the Web）才触发的 ⇒ 去掉这个标记，它就不再拦。
> ⚠️ **这不代表文件安全** —— 仍要核对下面的 sha256。

### 2. 签名链路**已就绪**（这一版未启用）

| 能力 | 状态 |
|---|---|
| 签名者匹配口径（CN 相等 + 多候选，绝不做「包含」匹配） | ✅ 已落地（客户端与构建期工具**共用同一份**） |
| 加严断言（`Valid` + RFC 3161 时间戳 + CN 相等） | ✅ 已落地 |
| 发版流水线（CI 打包 → 送签 → 人工审批 → 校验 → 发 Release） | ✅ 已落地，**这一版走的是「不签名」分支** |
| 签名政策文档（提交给审核方的那份） | ✅ 已提交申请，**审核中** |
| **真正的公开 OV 证书** | ⏳ **还没批下来** ⇒ **v0.2.6 起生效** |

⚠️ **为什么不等到签了名再发**：签名申请**批不批、何时批不由我们决定**，
而审核口径里我们最弱的一项是「可验证声誉」（0 star / 0 fork / ~73 下载）⇒
发版被外部审核无限期卡住并不划算；何况**产物至今本就未签名**（v0.2.4 就是未签名发的），
自动更新链路也**早已内置**「允许安装未签名的更新包」开关 ⇒ **签名从来没有卡住过功能**。

### 3. 发版流程**搬进 CI**

产物改由 GitHub Actions 构建（本机手工打包不再对外分发）—— 这是「可信构建」的前提，
也是将来能拿到签名的必要条件。

### 4. 校验值改成**逐版本给**

NSIS 安装器**内嵌构建时间戳** ⇒ **两次构建的字节必然不同**
⇒ sha256 **只能逐版本给**（本页末尾那一节就是发版流水线按**实际发布的字节**算出来的）。

## 二、下载

| 文件 | 说明 |
|---|---|
| `FN-Music-Setup-0.2.5.exe` | **安装版**（NSIS，可改安装目录） |
| `FN-Music-Portable-0.2.5.exe` | **便携版**（免安装，双击即用） |

**系统要求**：Windows 10 1809 及以上 / x64。

> ℹ️ **字节数与 sha256 在本页末尾**（「下载校验（sha256）」一节，**由发版流水线自动计算**
> ⇒ 核对的是**这一页真正发布出去的那两个文件**）。

### 自动更新用的清单（不用手动下载）

同一个 Release 里还挂着 `latest.json`（本项目自有的更新清单）——
本次发布的 3 个资产就是：**安装包 / 便携版 / `latest.json`**。

⚠️ **更新服务器地址留空即可**（v0.2.2 起的口径）：主进程会自动用项目自己的 Releases
（清单与安装包**同源**，符合客户端的校验规则）。若你想手动填：

```text
https://github.com/pure2199/sanlos-music/releases/latest/download
```

### 想用「一键更新」？这一版仍要手动开一次授权

本版产物**没有签名** ⇒ 想让应用自己装更新，需要：

1. 设置 →「更新」→ 勾选「**允许安装未签名的更新包**」→ **点「保存」**（**不保存不生效**）；
2. 「检查更新」→「下载更新」→「启动安装」。

⇒ 这一步**只放宽了「发布者身份」**：安装包仍必须 **SHA-512 与清单相符**、
必须与清单**同源**、路径不许越界。

## 三、怎么用

- **不用做任何设置**：装了就能用 —— 歌词来源、卡拉OK、队列、码率切换等与 v0.2.4 一致；
- **两种登录方式**：
  - **方式 A（推荐）**：填 **FN ID**，应用自动构造候选链路并并行探测，列出可达地址供你选；
  - **方式 B**：直接填 **NAS 地址 + 账号口令**（IP 只填 host 会自动补 `5666` / `5667`）。
- **没 NAS 也能用**：未登录时主区默认就是「本地音乐」页，可「添加文件 / 添加文件夹」
  导入本机音乐直接播；下载过的曲目也能直接播。
- ⚠️ **中继限速**：走中继链路（`https://<fnId>.fnos.net`）时播放会限速，
  客户端会带上 `mode=relay` Cookie —— 这是中继的**硬性关卡**，不带会返回 HTML 错误页。

## 四、已知影响（如实标注）

- ⚠️ **这一版的公开产物仍然没有代码签名** ⇒ Windows 仍会提示「未知发布者」。
  ⇒ 绕法见第一节（解除锁定 / `Unblock-File`）。
- ⚠️ **Smart App Control 的 Windows 11 是硬拦**（**没有**「仍要运行」按钮）⇒
  那类机器**装不上**这一版，**要等签名上线**（v0.2.6）。
  （Smart App Control 只出现在 **Windows 11 干净安装**上；从 Win10 原地升级的机器不受影响。）
- ⚠️ **企业 AppLocker / WDAC 策略**下未签名 exe 可能被直接拒 ⇒ 同上。
- ⚠️ **公开 Release 的资产是 3 个**：`latest.yml` 与 `*.blockmap` 是 electron-builder
  基于**未签名** exe 算出来的 ⇒ 将来签名改了字节它们就**已失效** ⇒ 不发布
  （本项目的自动更新走自己的 `latest.json` + SHA-512，本来就不用它们）。
- ⚠️ **校验值逐版本给** ⇒ 拿别处的哈希来核对**一定对不上**（NSIS 内嵌构建时间戳）。
- ⚠️ **「允许安装未签名的更新包」默认仍是关的**，需要你**手动勾选并保存**。
- ⚠️ **只对「确实没有签名」的包生效**：万一产物带上了签名而签名者与预期不符，
  **授权救不了**（那是另一个、更糟的情况）。
- ⚠️ **不校验证书信任链**（老口径不变）：我们只保证「这个文件确实由预期的人签的」，
  信任链由 **Windows 自己**判断。

## 五、安全边界（不可放宽）

- **渲染层永远拿不到凭证**：账号口令用 Windows **DPAPI**（`safeStorage`）加密后落盘；
  渲染层只能通过主进程的协议代理取数据，拿不到 token。
- **唯一出网通道**是应用自己的 **NAS 代理**；外部歌词源的抓取也全在主进程。
- **自动更新只查、只报**：不静默下载；下载后必须过 **SHA-512 校验**，
  且安装包地址必须**与更新清单同源**（清单不能把安装包指到别处）。
- **启动前再验一次**：签名 + SHA-512 都**再核对一遍**（用主进程自己缓存的清单，
  不是渲染进程给的值）；安装路径必须**仍在下载目录之内**。
