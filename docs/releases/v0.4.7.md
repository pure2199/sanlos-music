# Sanlos Music v0.4.7 —— 发布说明

相对 **v0.4.6** 的一次更新，**一件事**。

## 一、这一版改了什么

| 领域 | 内容 |
|---|---|
| **去掉备案号** | 设置 →「关于」里以前有一行「备案号」⇒ 现在**整行去掉**；单一真相源 `shared/appInfo.ts` 里的备案号字段也**一并删掉**（不留「界面上不显示、数据还在」的半吊子）；README 的软件信息表同步去掉了那一行。**开发者 / 公司 / 官网 / 项目地址都不变** |

## 二、① 「关于」页不再显示备案号

### 是什么

- **以前**：设置 →「关于」里有一行「备案号」（`桂ICP备202507161号-1`）；
- **现在**：**整行没了**。

### ⚠ 而且**不是「藏起来」

备案号**从数据层整个删掉**了 —— 单一真相源 `shared/appInfo.ts` 里的那个字段**本身没了**。

为什么要这么较真？因为「界面上不显示、数据还在」是**最容易被顺手加回去**的半吊子：
将来有人改版式时把那行加回来，谁都不会觉得是个问题。
⇒ 所以这个字段**删干净**，并用**断言钉住**「它不许回来」：

| 位置 | 钉住的是 |
|---|---|
| `test/app-info.test.ts` | 单一真相源里**不许**再有 `icp` 字段；**任何**字段的值里都不许出现备案号字样（防「换个字段名又塞回来」） |
| `test/settings-page.test.tsx` | 「关于」页**不许**出现备案号（既没有那个元素，也没有任何备案字样） |
| `e2e/smoke.spec.ts` | 真机跑一遍：**不许**出现备案号（既没有那个元素，也没有任何备案字样） |

### 什么都没少

**应用名称 / 版本 / 开发者 / 公司 / 官网 / 项目地址 —— 一行都没少。**

### ⚠ 历史记录**一个字都没动**

`docs/changelog.md` 的 T41 段、`docs/calibration.md`、
`docs/superpowers/specs/2026-11-05-sanlos-music-app-info-design.md`
里「当年有备案号」的那几行**按原样保留** ——
那是**历史事实**，不是现状声明（改历史 = 造假）。

### ⚠ 这一版**如实标注**的三点

1. ⚠ **歌单面板的排序 / 分页**在真机上**看不到**（真实账号没有歌单 ⇒ 控件不渲染）
   ⇒ 由自动化覆盖，**不假装真机验过**；
2. ⚠ **本版唯一的用户可感知变化**（「关于」页没有备案号）**真机验过了** ——
   判据是**双向**的：备案号**不在**，同时开发者 / 公司 / 官网**都还在**
   ⇒ 不会「整个关于块压根没渲染」也被判过；
3. ⚠ **产物仍然没有代码签名**（SignPath 申请已被拒）
   ⇒ 替代信任锚是 **GitHub 构建来源证明**（attestation）。

## 四、这一版的产物**仍然没有代码签名**

⚠ **公开产物继续以「未签名」形式发布** —— SignPath Foundation 的免费代码签名申请**已被拒**
（原因是**可见度不足**，不是代码质量）⇒ Windows SmartScreen 仍会拦（蓝色「Windows 已保护你的电脑」）。

✅ **替代信任锚 ＝ 构建来源证明**（GitHub 官方 artifact attestation / SLSA provenance）：
它证明每个产物确实是**本仓库的 CI** 从对应标签构建出来的，换一字节就验不过。

⇒ 怎么验 ⇒ 见 [README 的下载说明](../README.md) 与 [打包口径](./packaging.md) 第 7.10 节。
⇒ 本页末尾的 **sha256** 表是**逐字比对**用的（不想装 GitHub CLI 也能验）。

⇒ 校验值**只能逐版本给**，且只对**本 Release 页面**里那几个资产有效。

⇒ 逐字比对 **Release 页面末尾「下载校验（sha256）」** 那张表即可
（也可以用 `gh attestation verify "SanlosMusic-Setup-0.4.7.exe" --repo pure2199/sanlos-music` 验构建来源）。
