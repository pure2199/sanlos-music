# Sanlos Music v0.3.0 —— 发布说明

> 相对 **v0.2.9** 的一次更新：**歌词从「能不能找到词」变成「词准不准、准不准到每一个字」**，
> 外加**启动第一声不再炸出来**、**线上搜不到词时改读内嵌**。
>
> v0.2.9 发布的时候，六源兜底、真逐字、罗马音第三行、启动淡入、占位回落**都还没做**
> ⇒ 这一版把它们**一起**发出去。
>
> 这一版的产物**仍然没有代码签名** ⇒ 替代信任锚是 **GitHub 构建来源证明**（artifact attestation）。

发布日期：**2026-11-15**

## 一、这一版改了什么

### 1. 歌词源从 3 个变 6 个

设置 → 歌词来源现在有：

| 源 | 说明 |
|---|---|
| **网易云音乐** | 国内实测最快；**有罗马音**（日语歌多） |
| **lrclib.net** | 开源、免费；**没有**罗马音 |
| **QQ 音乐** | Lyricify 同款词源；**有罗马音**；真逐字（QRC） |
| **酷狗音乐** | **KRC 真逐字** |
| **酷我音乐** | **lrcx 真逐字 ＋ 翻译** |
| **咪咕音乐** | **mrc 真逐字 ＋ 翻译** |

**每个源都会被自动试一遍**（你选的那个先试）⇒ 冷门歌更容易拿到词。
每个源**各自限时**（3–8 秒，看它要跳几跳），全都试完才回落到本地。

### 2. 真逐字（卡拉OK 真跟嘴）

QQ / 酷狗 / 酷我 / 咪咕 / 网易云 都能拿到**词级**时间戳
⇒ 卡拉OK 的填色**跟着唱的那一个字**走，不是整行一起变色。

### 3. 第三行：罗马音

网易云上**有标注**的歌（绝大多数是日语歌）会在原文下面多显示**一行罗马音**；
**没有罗马音的歌如实不显示**（不占空行、不显示空的第三行）。

### 4. 翻译不再丢行、不再挂错行

以前网易云的翻译会**丢 14%–72% 的行**、还可能挂到别的句子上；
现在改成**以原文行为锚重新定时** ⇒ 实测**逐句对得上**、**零错行**
（6 组「原文 ↔ 副行」对账：网易云 98/98、酷我 96/96、咪咕 124/124 全对）。

### 5. 启动自动播放的第一声不再「炸」出来

以前启动后自动恢复播放，音乐会在约 1.5 秒后**一步到位**地响起来
（实测第一声就是稳态的 **71%**）；现在改成 **300 ms 线性淡入**
（实测出声瞬间只有稳态的 **42.8%**）⇒ 安静环境下不会被吓一跳。

### 6. 线上搜不到词时，改读内嵌歌词

有些源在「这歌没词」时会回一句占位提示（例如「此歌曲为纯音乐，请欣赏」）
—— 以前这句**被当成命中**，源链直接停下
⇒ 你明明有内嵌歌词却读不到。

现在占位**视同没匹配上** ⇒ 自动试下一个源，全都试完才回落**内嵌 → NAS**。

实测（《茨厂街（粤语谐剧·黄庆全 陈自成 吴金英）》）：

| 项 | 结果 |
|---|---|
| 内嵌歌词 | **12350 字符 / 265 行**（真对白） |
| 修复前 | 线上回「咪咕的占位」⇒ **内嵌根本没被读** |
| 修复后 | 线上回 `not-found` ⇒ 舞台显示**内嵌对白**，底部如实显示「**歌词来源：音频内嵌**」 |

### 真机实测（连**真实 NAS**）

| 项 | 结果 |
|---|---|
| 歌词源 | **5 个源 + lrclib 逐个**都**真的**被选中（界面上「歌词来源」= 实际命中的那个源），原文 / 翻译 / 罗马音与生产解析出来的期望**逐字相等** |
| 副行 | **零错行**（6 组对账全对，见上） |
| 启动淡入 | 观测到 **300.0 ms** 的爬坡；`playing` → 第一声 **31 ms**；**出声瞬间 / 稳态 = 42.8%**（无淡入时的基线是 **71%**） |
| 占位回落 | 线上 `not-found` ⇒ 舞台显示内嵌对白、「歌词来源：音频内嵌」 |

### 自动化

- `tsc --noEmit` ⇒ **0 error**；
- `vitest` ⇒ **126 files / 2684 passed / 0 failed**
  （v0.2.9 时是 118 / 2431 ⇒ 净增 **8** 个测试文件 / **253** 条用例，既有条数一条未减）；
- `npm run build` ⇒ **成功**；
- 全量 `playwright test`（CI 那套，不碰外网）⇒ **34 passed**。

## 二、⚠️ 已知影响（如实标注）

### 1. **英文歌没有罗马音**

网易云对**英文歌不提供罗马音**（实测 **6/6** 首都没有：Counting Stars / Shape of Taylor Swift /
Believer / Hello / Perfect / Let It Be）⇒ 英文歌只显示原文 + 翻译，
**第三行如实不出现**（**不是坏了**，是源里就没有）。

### 2. **冷门歌可能只有 1 行**

某个源没收录这首歌的词时，如实就只显示**能拿到的那几行**
（实测 QQ 对《残酷な天使のテーゼ》只有 1 行）。
⇒ 这是**既有行为**，不是这一版引入的。

### 3. **歌词源是第三方非官方接口**

6 个源都是**非官方公开接口**、随时可能变；某个源匹配不上时**自动试下一个**，
全都试完才回落到 NAS 自带的歌词（界面上会**如实显示实际命中的那个源**）。

### 4. **网易云搜索会临时限流**

连续搜索太多次时网易云会临时限流 ⇒ 那一次会**自动回落到 lrclib**
（lrclib 没有罗马音 ⇒ 那一轮第三行不出现）。

### 5. **淡入只治「启动自动播放」**

手动点歌 / 下一首 / 上一首**一律不淡入**（那是用户自己点的，本来就有心理准备）；
淡入**只改时间曲线、不改终点值** ⇒ 淡入结束后的音量与之前**完全一样**（音量滑块不动、界面不闪）。

### 6. **占位识别靠特征词**

判据是「短正文 + 占位特征词」⇒ 某个源若用**别的措辞**说「这歌没词」，
那一句**仍会被当成命中**；特征词表覆盖了中英两套常见写法
（纯音乐 / 纯音樂 / 请欣赏 / 暫無歌詞 / instrumental / music only / no lyrics …）。

### 7. **MP4 / M4A 读不到内嵌歌词**

MP4/M4A 的元数据（`moov`）在**文件尾**，而内嵌歌词是从**文件头**读的
⇒ 这两种容器的**内嵌歌词读不到**（线上有词时不受影响）。
⇒ **已知问题**，下一轮修（尾读文件尾）。

### 8. **线上只有 1 行（真歌词）而内嵌有几百行时，仍然用线上的**

这是「**线上优先**」这条政策 ⇒ 要「择优」需另拍板。

## 三、这一版的产物**仍然没有代码签名**

| 项 | 状态 |
|---|---|
| 代码签名 | ❌ **没有** ⇒ Windows 可能提示「未知发布者」⇒ **蓝框怎么绕**见 [README 的下载说明](../README.md) |
| 构建来源证明 | ✅ **有**（GitHub artifact attestation / SLSA provenance）⇒ 证明每个产物确实是**本仓库的 CI** 从对应标签构建出来的，**换一字节就验不过** |

⚠️ **为什么还是没签名**：SignPath Foundation 的免费签名申请**已被拒**
（2026-11-12，原因是**可见度不足**，不是代码质量）
⇒ 全球范围内对个人/小团队而言，「**公开可信的代码签名证书**」目前只剩**付费**一条路。

⚠️ **SmartScreen 蓝框可以绕**（不是「无法绕过」）：

1. 右键安装包 → **属性** → 底部勾「**解除锁定**」→ 应用 ⇒ **蓝框直接消失**；
2. 或者用**应用内的一键更新**下载 —— 应用自己下载的包**不带「来自互联网」标记** ⇒ 安装时不弹蓝框。

⚠️ 但 **Smart App Control（Windows 11 的「应用控制」）是硬拦** —— 那条路未签名绕不过。

## 五、这一版的校验值

⚠️ NSIS 安装器**内嵌构建时间戳** ⇒ **两次构建的字节必然不同**
⇒ 校验值**只能逐版本给**，且只对**本 Release 页面**里那两个资产有效。

⇒ 逐字比对 **Release 页面末尾「下载校验（sha256）」** 那张表即可
（也可以用 `gh attestation verify "SanlosMusic-Setup-0.3.0.exe" --repo pure2199/sanlos-music` 验构建来源）。

这一版的两个产物（文件名与软件名一致，**不带空格**）：

| 文件 | 说明 |
|---|---|

1. **启动自动播放的第一声**还吓不吓人？（应该只从稳态的 ~43% 慢慢爬上来）
2. **续播的位置**准不准？（差个几秒属正常 —— 每 10 秒才记一次；**超过 10 秒**请告诉我们）

> ⚠️ 如果某首歌显示「暂无歌词」但**你确定它有词**，多半是那首歌**所有源都没有收录**
> （源链会自己往下试，全都试完才回落）⇒ 把歌名告诉我们，我们看一眼是源的问题还是匹配的问题。
