## 二、⚠ v0.4.2 漏掉的那一处（**如实标注**）

### 1. 事情是怎么发生的

v0.4.2 把**里层代号全改了**（包名 / appId / 内部协议 / 工具脚本 / 仓库默认分支），
连带改了本机 `localStorage` 里的**四个键**：

| 键（v0.4.1 时代） | 存的是什么 | v0.4.2 有没有做「旧键回落」 |
|---|---|---|
| `fnmusic-local-history` | 播放历史 | ✅ 有 |
| `fnmusic-resume` | 续播位置 | ✅ 有 |
| `fnmusic-lyric-overrides` | 按歌指定歌词源 | ✅ 有 |
| **`fnmusic-audiobook-state`** | **「有声」页那次全库扫描的结果 ＋ 你的手工改判** | ❌ **漏了** |

⇒ v0.4.2 **读不到**第四个 ⇒ 下面三条后果：

| 后果 | 说明 |
|---|---|
| **有声读物的自动判定失效** | 「有声读物被误配桌面歌词」那条老毛病会回来（**v0.4.1 修过一次，v0.4.2 又漏了**） |
| **手工改判丢失** | 你在「有声」页手动标过 / 取消过的东西，看不见了 |
| **「有声」页自动全库重扫** | 进一次页面就重扫一遍 —— 实测 **87 页 / 6–47 分钟**，期间还在吃 NAS 流量 |

### 2. v0.4.3 怎么修的

**新键没有的时候，才回落去读旧键**（旧键**只读、绝不删**），
而且**写入只落新键** ⇒ **一次性迁移**、**幂等**、**零删除**。

⇒ 旧记录**照常在**，而且**不会**被旧数据顶掉（新键优先）。

### 3. 「我已经在 v0.4.2 上用过一阵了」怎么办

| 你的情况 | v0.4.3 装上之后 |
|---|---|
| **进过「有声」页**（触发过重扫） | 重扫的结果当时就写进**新键**了 ⇒ v0.4.3 **直接用它**，无需迁移 |
| **没进过「有声」页** | 从**旧键**回落 ⇒ 你之前那次扫描的结果**回来了** ⇒ **不用再扫一遍** |

### 4. ⚠ **一个还没修的老问题**（如实标注）

「有声」页全库扫描时，**每扫完一页就落盘一次**，用的是**启动那一刻**的 `overrides` 快照
⇒ 如果你**在扫描进行中**手工改判了某部作品，**那次改判有可能被扫描覆盖**。

⇒ 这是 **既有问题**（v0.4.2 就有），**v0.4.3 不修它** ⇒ 已记为**待修项**，会另出一版。
（不影响日常使用：改判完**等扫描结束再改一次**即可。）

## 四、这一版的产物**仍然没有代码签名**

| 项 | 状态 |
|---|---|
| 代码签名 | ❌ **没有** ⇒ Windows 可能提示「未知发布者」⇒ **蓝框怎么绕**见 [README 的下载说明](../README.md) |
| 构建来源证明 | ✅ **有**（GitHub artifact attestation / SLSA provenance）⇒ 证明每个产物确实是**本仓库的 CI** 从对应标签构建出来的，**换一字节就验不过** |

⚠ **为什么还是没签名**：SignPath Foundation 的免费签名申请**已被拒**
（2026-11-12，原因是**可见度不足**，不是代码质量）
⇒ 全球范围内对个人/小团队而言，「**公开可信的代码签名证书**」目前只剩**付费**一条路。

⚠ **SmartScreen 蓝框可以绕**（不是「无法绕过」）：

1. 右键安装包 → **属性** → 底部勾「**解除锁定**」→ 应用 ⇒ **蓝框直接消失**；
2. 或者用**应用内的一键更新**下载 —— 应用自己下载的包**不带「来自互联网」标记** ⇒ 安装时不弹蓝框。

⚠ 但 **Smart App Control（Windows 11 的「应用控制」）是硬拦** —— 那条路未签名绕不过。
