# Sanlos Music v0.2.6 —— 发布说明

> 相对 **v0.2.5** 的一次更新：**三处「用户看得见」的改进 + 一次文档校准**。
> 这一版的产物**仍然没有代码签名** —— 免费签名申请**已被拒**（可见度不足，不是代码质量）
> ⇒ 替代信任锚是 **GitHub 构建来源证明**（artifact attestation）。

发布日期：**2026-11-12**

---

## 一、这一版改了什么

### 1. 用户数据目录改名为「Sanlos Music」（并**自动迁移**旧目录）

以前用户数据文件夹叫 `fnmusic-desktop`（飞牛时代的名字），软件改名后它一直没跟着变。
这一版起，它叫：

```
%APPDATA%\Sanlos Music\
```

⚠️ **升级时不需要做任何操作**：启动时会把旧目录
`%APPDATA%\fnmusic-desktop` 里的内容**整体搬过来**
（偏好 `prefs.json`、登录凭据 `session.bin`、本地曲目登记 `local-library.json`，
以及 Chromium 自己的缓存与 Cookie）⇒ **配置与登录态都还在**。

| 情况 | 结果 |
|---|---|
| 全新安装 | 没有旧目录可搬 ⇒ 直接用新目录 |
| 从 v0.2.5 升级 | 旧目录内容**逐项搬进**新目录 ⇒ 搬空后旧目录自动消失 |
| 新目录里已有同名文件 | ⚠️ **不覆盖**（新目录里的更新）⇒ 旧的那份**留在旧目录**里，**不丢数据** |
| 搬不动（文件被占用 / 跨磁盘） | 降级为「复制 + 保留源」⇒ 仍然不丢数据；下次启动会再试一次 |

### 2. 自动更新的临时安装包**不再越堆越多**

自动更新把安装包下载到 `%TEMP%\fnmusic-update\`。以前这个目录**只进不出** ——
每更新一版就多留一份 **86 MB** 的旧安装包（外加下载中断留下的 `.part` 碎片）。

这一版起：

- **启动时**清空这个目录 —— 上一轮会话留下的安装包已经没有用了（下载状态是内存态，
  重启后本来就要重新下载）⇒ 不会白占磁盘；
- **下载成功后**只保留本次下载的那一个 ⇒ 同一次会话里连下两版不会占两份；
- ⚠️ 只删**普通文件**，遇到目录一律跳过；删不掉就算了，**不影响启动和下载**。

### 3. Windows 11 主题的强调色改由**封面主色**决定

规格里写着「Windows 11 Fluent 风：强调色 = 取自封面取色的 Fluent 强调色」，
这一条是双主题表里最后没落地的。现在它落地了：

- 播放时，界面的强调色（按钮、链接、焦点环）会跟着**当前歌曲封面的主色**变；
- ⚠️ **只对「Windows 11 风」生效**（「Apple 风」按规格是固定的单色）；
- ⚠️ **取不到色时不改**（没有封面 / 封面加载失败 / 灰白封面没有色相）⇒ 保持主题默认色；
- ⚠️ 主色会被**校正**过：饱和度与亮度落在 Fluent 的观感区间，
  并且**保证白字压在上面的对比度 ≥ 4.5**（WCAG AA）⇒ 不会出现「亮色按钮上白字看不见」。

> ℹ️ **怎么看**：设置 → 外观 → 主题 → 切到「Windows 11 风」，然后换几首歌看强调色变化。

### 4. 文档校准（一批过时数据被更正）

`docs/calibration.md` 里有 5 处数据已经过时，其中两处会**直接误导判断**：

- 单元测试条数（1228 → **2304 条 / 110 个文件**）与 E2E 条数（4 → **34 条**）
  —— 现在都改成**实测值**，并标注了测量日期；
- 「`auth-lost`（续期失败 → 回登录页）**尚未实现**」—— ⚠️ 那是**假的**，它
  T19 就实现了（`src/api/client.ts` → `src/App.tsx` → 登录页提示），
  照着它会误判成缺功能；现已更正并写明实现位置与回归测试位置；
- 总览补上了「**公开发布：v0.2.5 已发布**」这一行（此前这份总览完全没提发布状态）。

## 二、这一版的产物**仍然没有代码签名**

| 项 | 状态 |
|---|---|
| 代码签名 | ❌ **没有** ⇒ Windows 可能提示「未知发布者」⇒ **蓝框怎么绕**见 [README 的下载说明](../README.md) |
| 构建来源证明 | ✅ **有**（GitHub artifact attestation / SLSA provenance）⇒ 证明每个产物确实是**本仓库的 CI** 从对应标签构建出来的，**换一字节就验不过** |

⚠️ **为什么还是没签名**：SignPath Foundation 的免费签名申请**已被拒**
（原因是**可见度不足**，不是代码质量）⇒ 全球范围内对个人/小团队而言，
「公开可信的代码签名证书」目前只剩**付费**一条路。

⚠️ **SmartScreen 蓝框可以绕**（不是「无法绕过」）：

1. 右键安装包 → **属性** → 底部勾「**解除锁定**」→ 应用 ⇒ **蓝框直接消失**；
2. 或者用**应用内的一键更新**下载 —— 应用自己下载的包**不带「来自互联网」标记** ⇒ 安装时不弹蓝框。

⚠️ 但 **Smart App Control（Windows 11 的「应用控制」）是硬拦** —— 那条路未签名绕不过。

## 三、升级须知

| 项 | 说明 |
|---|---|
| **是否需要手动迁移数据** | **不需要** ⇒ 启动时自动搬 |
| **回滚到 v0.2.5 会怎样** | 旧目录已被搬空 ⇒ 旧版本会显示「未登录 + 偏好回默认」⇒ **数据没丢**，在 v0.2.6 里改回去、或让用户重新登录即可 |
| **安装路径 / 注册表 / 升级链** | **完全不变**（`appId` 没动）⇒ 可以直接覆盖安装 |
| **已知限制** | 用户数据目录改名**只在这一版生效一次**；若再改目录名，同样会自动迁移 |

## 四、这一版的校验值

⚠️ NSIS 安装器**内嵌构建时间戳** ⇒ **两次构建的字节必然不同**
⇒ 校验值**只能逐版本给**，且只对**本 Release 页面**里那两个资产有效。

⇒ 逐字比对 **Release 页面末尾「下载校验（sha256）」** 那张表即可
（也可以用 `gh attestation verify FN-Music-Setup-0.2.6.exe --repo pure2199/sanlos-music` 验构建来源）。

## 五、验完这一版请帮我们看三件事

1. **Windows 11 风**下换几首歌 ⇒ 强调色随封面主色变化，观感是否可接受；
2. **全屏播放页**的歌词在**封面取色背景**上是否清晰（`--accent` 与背景的对比度）；
3. 升级后**偏好与登录态是否还在**（应当都在，且旧的 `fnmusic-desktop` 文件夹已消失）。
