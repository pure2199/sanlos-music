# Sanlos Music v0.4.4 —— 发布说明

> 相对 **v0.4.3** 的一次**更新**，一共三件事：
> **① 「有声」页改成按服务端的目录浏览**（不用再把 17.3 万首全扫一遍）；
> **② 修掉「扫描时把你手工改的判覆盖掉」那个老毛病**；
> **③ 把「服务端不能浏览目录」这句过时的说明改对**。

> ⚠ **唯一要动手的一步**：这一版 **appId 没变** ⇒ **是原地升级** ⇒ **直接装就行，不用先卸载 v0.4.3**。

>
> 这一版的产物**仍然没有代码签名** ⇒ 替代信任锚是 **GitHub 构建来源证明**（artifact attestation）。

发布日期：**2026-11-20**

## 二、① 「有声」页改成按服务端的目录浏览

### 事情是怎么发生的

「那个文件夹里的都是有声小说」这件事，一直是**真的**；只是以前客户端**没法只取那一个文件夹**
⇒ 只能把整个曲库扫一遍，再按路径里的目录名挑出你想要的那部分。

现在**服务端支持按目录浏览**了（飞牛更新后的新接口）⇒ 客户端**直接去那个文件夹取**，
不用绕那一大圈。

⇒ **「判定 / 归并 / 卡片 / 点开 / 手工改判」全部原样保留**
（只换了「数据从哪儿来」，**没换「怎么判」**）。

### ⚠ 老服务端也能用

万一你的服务端还没更新 ⇒ 客户端会**自动**改回扫全库（慢一点，但**结果一样**）
⇒ 状态行会**如实告诉你**「已改用全库扫描」。

### 用户看得见的变化（**就这三处**）

| 位置 | 之前 | 现在 |
|---|---|---|
| 「有声」页的提示句 | 「本客户端目前是扫一遍曲库、再按目录名挑出这个文件夹里的作品」 | 「本客户端**按服务端目录浏览**出这个文件夹里的作品」 |
| 扫描中的状态行 | 「正在扫描…第 N 页 / 共 M 页（已扫 X 首）」 | 「正在按目录浏览…已取 X 首（走过的目录 N 个）」 |
| 扫完的状态行 | 「上次扫描：… · 目录「有声小说」· 9 部」 | 「上次扫描：… · 目录「有声小说」· 9 部（**/vol02/…/有声小说**）」⇒ **多了目录的完整路径**，你看得见它到底扫的是哪个目录 |

⚠ **空态那一句一个字没动**（「当前曲库里没有识别到有声读物」）⇒ 行为不变。

## 三、② 修掉「扫描时把你手工改的判覆盖掉」

### 之前会发生什么

「有声」页扫描时**每扫完一页就落盘一次**，落盘写的是**扫描启动那一刻**的「手工改判」快照
⇒ 如果你在**扫描还在跑**的时候手工标了某部作品「这不是有声」
⇒ 那次改判**有可能被扫描覆盖掉** ⇒ 界面上你刚点的那一下**当场消失**。

### 现在

**扫描不再拥有「手工改判」的写权限** —— 它只写自己那几个字段，
「手工改判」一律取**内存里的当前值** ⇒ 扫描期间你怎么改都**不会丢**。

⇒ 顺带也修了另一条同类毛病：「封面」补拉完之后回写落盘，同样不会再覆盖你的改判。

## 四、③ 把「服务端不能浏览目录」这句过时的说明改对

飞牛更新之后，服务端**已经支持**按目录浏览了
⇒ 文档与界面里「服务端不能浏览目录」这句话**已经不成立**
⇒ 这一版把 **6 处**（README 3 处 + 「有声」页 2 处 + 1 处代码注释）**统一改准**。

⚠ 顺带加了 **防回退的钉子**（自动化测试）⇒ 以后谁把旧说法抄回去，测试会红。

## 五、真机复验状态（**⏳ 待装版复验**）

⚠ **先把口径说清楚**：下面这组数字是**本版代码**在**真实 NAS / 真实账号**上的实测，
跑的是**本机自己打的、带本版代码的产物**（**就是**安装器要装的那份 exe ⇒ 口径等价），
**不是** GitHub Release 产物 —— 那份正由 CI 构建 ⇒ **装版后还要再复验一遍**，
结果在装版复验后**回填本节**。

测的是**本机这台 Windows 10.0.26300 x64**、**真实 NAS**、**真实账号**下的一份**隔离 userData**
（只复制**真实会话** ⇒ 真实账号 + 真 NAS，但**不碰**你本机的偏好 / 下载目录 / 扫描结果）。

### ⚠ 复验的前提：**已装的 v0.4.3 验不到新行为**

所以复验时打了一份**带本版代码**的产物，直接跑它，
**没有**覆盖你已装的 v0.4.3、**没有**动注册表。

### 对照组 ＝ **已装的 v0.4.3**（同机 / 同账号 / 同数据 / 同一天）

| 复验项 | v0.4.3（旧路径） | **v0.4.4（这一版）** | 结论 |
|---|---|---|---|
| 「有声」页扫描耗时 | **56 041 ms** | **9 133 ms**（第二次 **6 594 ms**） | ✅ **快 6–8 倍** |
| `/track/list`（全库列表接口）调用 | **88 次**（87 页 ＋ 1） | **扫描期间 0 次** | ✅ **没再全库扫** |
| `/folder-view/list`（目录浏览接口）调用 | 0 | **69 次** | ✅ **走的是目录浏览** |
| 作品列表 | **9 部** | **9 部（逐字一致）** | ✅ **判定口径没变** |
| 落盘的版本号 | 3 | **3（没升）** | ✅ **你上次扫的结果直接还在** |
| 落盘的曲目数 | 173 671 | **5 244**（= 那个目录递归共有的首数） | ✅ **只取了那个文件夹** |
| 落盘的目录路径 | 无此字段 | **`["/vol02/1000-0-3d135437/有声小说"]`** | ✅ **记下了扫的是哪个目录** |

> **「`/track/list` 调用 0 次」的口径**：真机上**整个应用在跑** ⇒ 默认落地页也会拉**一小页**歌曲列表
> ⇒ 那一次发生在**启动后 0.2 秒**，比点开「有声」页**早了近 26 秒** ⇒ **与扫描无关**；
> 扫描那一段里它**一次都没被调用**。
> （交叉验证：v0.4.3 那 88 次 = 87 页 ＋ **同一个那一次** ⇒ 两边同源。）

### 对照组②：「那个文件夹**不存在**」时

把目录名改成一个**不存在**的名字再扫 ⇒ 客户端**如实说没找到**：

> 「服务端的目录里**没找到**叫「xxx」的文件夹 ⇒ 请确认它在音乐服务的曲库里（或换个目录名再试）。」

⇒ 而且它**没有**偷偷改回扫全库（扫描接口的调用次数**没增加**）
⇒ **「没找到」和「服务端不支持」是分得开的**：前者不会白扫一遍全库。

### ⚠ 这一版**如实标注**的两点

1. **产物仍然没有代码签名**（见下一节）⇒ 替代信任锚是 **GitHub 构建来源证明**（artifact attestation）。
2. **落盘里「曲目封面」那个 id 变了** —— 按目录浏览拿回来的曲目**没有独立的封面 id**（服务端给的就是专辑封面）
   ⇒ 该字段**不用于显示**（卡片一律用专辑封面）、**判定也不看它** ⇒ **你看不到任何差别**。

## 六、这一版的产物**仍然没有代码签名**

| 项 | 状态 |
|---|---|
| 代码签名 | ❌ **没有** ⇒ Windows 可能提示「未知发布者」⇒ **蓝框怎么绕**见 [README 的下载说明](../README.md) |
| 构建来源证明 | ✅ **有**（GitHub artifact attestation / SLSA provenance）⇒ 证明每个产物确实是**本仓库的 CI** 从对应标签构建出来的，**换一字节就验不过** |

⚠ **为什么还是没签名**：SignPath Foundation 的免费签名申请**已被拒**
（2026-11-12，原因是**可见度不足**，不是代码质量）
⇒ 全球范围内对个人/小团队而言，「**公开可信的代码签名证书**」目前只剩**付费**一条路。

⚠ **SmartScreen 蓝框可以绕**（不是「无法绕过」）：

1. 右键安装包 → **属性** → 底部勾「**解除锁定**」→ 应用 ⇒ **蓝框直接消失**；
2. 或者用**应用内的一键更新**下载 —— 应用自己下载的包**不带「来自互联网」标记** ⇒ 安装时不弹蓝框。

⚠ 但 **Smart App Control（Windows 11 的「应用控制」）是硬拦** —— 那条路未签名绕不过。
