# Sanlos Music v0.4.6 —— 发布说明

相对 **v0.4.5** 的一次更新，**八件事**（三件用户能感知 ＋ 五件开发期）。

## 一、这一版改了什么

| 领域 | 内容 |
|---|---|
| **代理层故障分类** | NAS 连不上 / 请求超时 / 未登录，这些**代理层故障**以前一律被当成「服务端业务拒绝」⇒ 现在**分得清**了：网络故障说「连不上音乐服务」（**可重试**），**会话失效会真的回登录页**（以前会卡在「已登录、但每个请求都失败」）；服务端自己的业务码**语义一点没变** |
| **mock server 端口分配** | 开发用的 mock server 以前**拿到端口 0 也当成功**（那个端口根本连不上）⇒ 现在多一道判定（端口 0 与 fetch 的禁用端口都算**不可用**），绑定失败**换一个重试**（最多 20 次），绑定失败也**不再把整个测试进程带崩** |
| **扫描落盘保留已补拉的专辑封面** | 「有声」页补拉到的专辑封面以前**每次扫描都被冲掉**（卡片永远显示占位图、每次进来都要重拉一次）⇒ 现在落盘会**保留已经知道的封面**；并把「未知」与「确认没有」**分清**（扫描没查过 ⇒ 只能是「未知」） |
| **签名政策总入口 ＋ 代码所有权** | README 加了 `### Code signing policy` 小节（**索引**：政策原文 / 操作手册 / 无证书期发版各在哪）；新建 `.github/CODEOWNERS`（发版工作流、打包脚本、签名政策等路径都点名维护者） |
| **打包产物跨卷搬运** | `SANLOS_PACK_OUTPUT` 指到**别的盘**时，改名会报 EXDEV（产物搬不过去，提示语还说「目标位置被占用」⇒ 误导）⇒ 现在自动回退「复制 + 删源」；实在搬不动就**如实保留**在暂存目录并说明 |
| **歌单面板排序 / 分页** | 「加入歌单」面板里的歌单以前**按服务端返回顺序**排、**不分页**（歌单多起来只能靠滚动找）⇒ 现在可**按名称 / 更新时间排序**、**每页 20 条**分页；**搜索或换排序会自动回到第 1 页**（否则搜到的结果落在第 2 页 ⇒ 眼前一片空白） |
| **维护者文档订正** | T119 那张端点表里 `sharedLibrary` 一族的最后一个端点**写错了**（`reconnect-check` 应为 `/shared-library/reconnect/check`）⇒ 按「历史段不篡改」的纪律**原表保留不动**，在**紧邻表下方**加了订正标注 ＋ 钉子测试（防止有人「好心」把历史直接改对） |
| **开发期回归稳定性** | 「取消排队中的任务」那条下载用例以前只等两个宏任务（要等真磁盘 IO 走完）⇒ 全量回归里**偶发红**（3 次里 1 次）⇒ 现在改成**等条件成立**（带上限观察窗），**断言一条没改**；只影响开发期测试，对成品**无感** |

## 二、① 代理层故障不再被当成「服务端业务拒绝」

### 是什么

以前，NAS 连不上、请求超时、没登录 —— 这些**代理层故障**一律被说成「服务端业务拒绝」。
更要命的是：**会话已经失效**时，界面还显示「已登录」⇒ 每个请求都失败，人却不知道该去重新登录。

现在客户端**分得清**这三类：

| 类别 | 什么时候 | 你会看到 |
|---|---|---|
| **网络故障** | 请求超时 / 网络不可达 | 「无法连接音乐服务」——**可以重试** |
| **会话失效** | 未连接 / 未登录 / 续期失败 | **真的回到登录页**（以前卡在「已登录、但每个请求都失败」） |
| **请求本身不合法** | 地址 / 路径 / 请求体不合法 | 说清是客户端请求的问题，**不冒充**服务端拒绝 |

⚠ **服务端自己的业务码，语义一点没变**（「没这首歌」「没权限」还是老样子）。
⚠ **老服务端不受影响**：认不出的响应照样按原来的方式处理。

## 三、② 「有声」页的封面不再被扫描冲掉

- **以前**：进「有声」页补拉到的专辑封面，**每次扫描都被冲掉**
  ⇒ 卡片永远显示占位图、每次进来都要重拉一次；
- **现在**：扫描落盘**保留已经知道的封面**；
- 另外把「**没查过**」与「**确实没有**」**分清**了：扫描没查过 ⇒ 只能是「未知」
  ⇒ 不会把「不知道」写成「没有」（那会让页面**永远不再补拉**）。

## 四、③ 「加入歌单」面板能排序、能分页

- **以前**：面板里的歌单**按服务端返回顺序**排、**不分页**（歌单多起来只能靠滚动找）；
- **现在**：可**按名称 / 更新时间排序**、**每页 20 条**分页；
- **搜索或换排序会自动回到第 1 页**（否则搜到的结果落在第 2 页 ⇒ 眼前一片空白）。
