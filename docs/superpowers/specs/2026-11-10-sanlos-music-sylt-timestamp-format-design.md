# T84 规格：`SYLT` 的「时间戳格式 = 2」按**毫秒**读（跟随 mutagen 的实际约定）

> 状态：**已实施**（规格先行 = 本文件；实现 = 下一个 commit）
> 关联：T83（音频内嵌歌词）规格 `2026-11-10-sanlos-music-embedded-lyric-design.md`
> 触发：T83 收尾时用**网上下载的真实音频文件**做真机复验 ⇒ 发现真文件读不出歌词。

## 1. 问题（真实文件暴露的，**不是推测**）

### 1.1 复现

T83 落地后，拿三个**真实**文件（网上下载，**不是自造**）复验：

| 文件 | 来源 | 期望 | 实际 |
|---|---|---|---|
| `flac-lyrics.flac` | 真 FLAC + `LYRICS` 注释 | 读出**行级**歌词 | ✅ |
| `countdown.mp3` | 真 mp3，**没有**任何歌词标签 | 无内嵌歌词（行为与今天一致） | ✅ |
| `karaoke.mp3` | CC BY-SA 的 `SYLT` 语料 | **真逐字** ⇒ 进卡拉OK | ❌ **一个字都没读出来** |
| `utf8-desc.mp3` / `utf16-nodesc.mp3` / `multiline.mp3` | 同上 | 行级 | ❌ 同样读不出来 |

⇒ FLAC 路径没问题；**MP3 的 `SYLT` 路径整个失灵**。

### 1.2 根因（字节级）

`karaoke.mp3` 的 ID3v2.4 标签里：

```
帧 SYLT size=98 @125
  编码=3(UTF-8) 语言=eng 时间戳格式=2 内容类型=1
  十六进制：03 65 6e 67 02 01 00 | 74 65 6e 00 | 00 00 00 20 | 6e 69 6e 65 00 | 00 00 03 e8 | …
```

- 第 4 字节（偏移 4）= `02` ⇒ **时间戳格式 = 2**；
- 随后的时间戳是 `0x20`(32)、`0x3e8`(1000)、`0x7d0`(2000) … `0x2710`(10000)
  ⇒ 这是**毫秒**（音频总长 **10.97 秒**；若真是 MPEG 帧号，10000 帧 ≈ 261 秒 ⇒ 不可能）；
- ID3v2 规范说「格式 2 = MPEG 帧号」⇒ **文件声明与规范不符**。

### 1.3 为什么这不是「个别坏文件」

mutagen（最流行的 Python 标签库）自己的实现写着：

```python
def __str__(self):
    unit = 'fr' if self.format == 1 else 'ms'
```

⇒ **mutagen 的约定与 ID3 规范正好相反**（它把 1 当帧号、其它当毫秒）；
而这批语料的生成脚本是 `data.setdefault('format', 2)`
⇒ **mutagen 写出来的 `SYLT` 一律是「格式 2 + 毫秒」**。

⇒ 现实里最常见的 `SYLT` 文件（凡是用 mutagen 写的：lollypop 的测试集、各类 Python 标签工具）
**恰好都是我们整帧放弃的那一档**
⇒ 按规范实现 ⇒ **真机上这个功能等于没有**。

## 2. 决策（用户 2026-11-10 拍板）

> **「按毫秒读（跟随 mutagen 实际约定）」**

⚠️ 这**推翻了 T83 规格 §4.5 的「格式 2 ⇒ 整帧放弃」**（前提被显式推翻 ⇒ 相应断言改写为新行为）。

## 3. 行为规范

| 时间戳格式 | 处理 | 理由 |
|---|---|---|
| `1` | 按**毫秒**读 | ID3v2 规范 = 绝对时间 |
| `2` | 按**毫秒**读 | mutagen 系的实际约定（现实中最常见） |
| 其它（`0` / `3+`） | **整帧放弃** | 真不知道是啥 ⇒ **不猜** |

⚠️ **风险（如实标注，不藏）**：若某个文件**真按规范**存了 MPEG 帧号（格式 2 + 帧号），
我们会把它当毫秒 ⇒ 数值比真实毫秒**小得多** ⇒ 时间戳偏早 ⇒ **卡拉OK 走偏**。
⚠️ 这类文件**极少**（主流标签工具写的都是「格式 2 + 毫秒」），
且**不会崩、不会显示错歌词**，只是时间偏
⇒ 判定优先级：**有歌词 > 时间绝对准确**（与 T81「不假装逐字」不冲突：这里只影响时间，不影响「有没有词」）。
