# T73 —— 歌词多源回退 + 切源即时生效（规格）

> 用户指令（2026-11-09）：
> 「切换歌词源，桌面歌词为什么不能同步，全屏歌词有显示，桌面歌词没有显示，
> 他一个歌词源匹配不到为什么不自己切换下一个歌词源，先匹配完线上的，再到 NAS 本地」

---

## ① 现状（**已查证**，非推测）

### ①-A 「切源后桌面歌词不同步」

三条歌词页面的取词是**两套**代码：

| 页面 | 取词代码 | 什么时候重新取词 |
|---|---|---|
| 全屏歌词舞台 | `src/pages/FullPlayerPage.tsx` 自己调 `loadLyricEntries` | 页面挂载 / 歌变了 / **优先级变了**（effect 依赖里） |
| 经典悬浮窗 + 灵动态词岛 | `src/player/lyricOverlay.ts`（`installLyricOverlay`） | **只有三种**：切歌、桌面歌词从关变开、输出延迟变化（只重推不重取） |

⇒ **改歌词源 / 改优先级 / 改模板时，桌面歌词既不重取、也不重推** ⇒ 一直停在旧内容
（多半是「暂无歌词」）⇒ **就是用户看到的现象**。

⚠️ 顺带查证：全屏页的 `externalFetcher` 是 `useState` 的**惰性初始化**（只跑一次）⇒
**页面已经开着**时切源，它也不会立刻重取（要重新打开才看得到新源）。

### ①-B 「一个源匹配不到不试下一个」

- 主进程 `electron/lyricProvider.ts` 的 `fetchExternalLyric(source, template, query)`
  ⇒ **一次只试一个源**：命中即返回；`not-found` / `error` 也直接返回。
- 渲染层 `src/player/lyricSource.ts` 的 `loadOnlineFirst`
  ⇒ 线上（**那一个**源）匹配不上 / 报错 / 超时 ⇒ **回落 NAS 本地** ✓（这步已经有了）。

⇒ 缺的正是中间那步：**线上源之间也要互相回落**。

---

## ② 口径（定死）

1. **「歌词源」单选 = 首选源**（不再表示「只用这个源」）：
   - 先试**用户选的那个**；
   - 匹配不到 → 按固定顺序试其余线上源：**网易云 → lrclib → QQ 音乐 → 自定义模板**；
     （用户没配模板 ⇒ `custom` **不进链**）
   - 全部不行（`not-found` / 全部坏了）⇒ **回落 NAS 本地**（渲染层既有逻辑 ✓ 一行不改）。
2. **「不用外部」= 纯本地**：**一次网络请求都不发**（不变；E2E 夹具依赖这条）。
3. **命中哪个源就显示哪个源**（如实说明，不装作是首选源）。
4. **切源 / 切优先级 / 改模板 ⇒ 三处歌词页面立刻重新取词**（经典悬浮窗 / 灵动态词岛 /
   全屏歌词舞台），**不等下一首歌**。
5. **每个线上源各自限时 3 秒**（实测正常源 < 500ms；慢的源不值得等）；
   线上**总**预算 10 秒 → **12 秒**（4 源 × 3 秒）。
6. 源链**只在主进程实现**：IPC 契约（`lyric:fetch`）与渲染层取词接口**一字不改**
   ⇒ 渲染层不知道有几个源，只知道「线上」这一坨。

## ③ 设计

### ③-A 主进程：单源 → 源链（`electron/lyricProvider.ts`）

```
首选源 → 网易云 → lrclib → QQ → 自定义模板（有模板才进链）
```

- **命中（`status: 'ok'` 且原文非空）⇒ 立刻返回**，不再问后面的源；
- `not-found` ⇒ 试下一个；
- `error` ⇒ **也试下一个**（一个源坏了不该让整条链断掉），但**记住第一个错误**；
- 链走完仍没有 ⇒ 返回**首选源那个错误**（若首选源是 `not-found` 则返回第一个错误，
  都没有则 `not-found`）；
- **每源 3 秒**（`Promise.race` + 定时器；超时的请求**继续跑**，结果丢弃）；
- 缓存键**不变**（含首选源 + 模板）⇒ 缓存的是**整条链的结果** ✓ 切源后键变 ⇒ 立刻重取 ✓。

### ③-B 渲染层：桌面歌词跟随切源（`src/player/lyricOverlay.ts`）

订阅 `useAppPrefsStore` 的 `lyricSource` / `lyricPriority` / `lyricTemplate`：
变了 ⇒ `publishTrack(true)`（**强制重取 + 重推**）⇒ 经典窗与词岛立刻换内容。

⚠️ 只在**桌面歌词开着**时重取（关着就不多打 NAS —— 与既有口径一致）。

### ③-C 全屏页：切源也重取 + 显示来源（`src/pages/FullPlayerPage.tsx`）

- effect 依赖补 `lyricSource` / `lyricTemplate` ⇒ **页面开着**时切源也重取；
- 歌词下方显示「来源：网易云 / lrclib / …」。

### ③-D 透传实际命中的源（`src/player/lyricSource.ts`）

`LyricLoadResult` 增加 `externalSource?: LyricSource`（**可选字段**，既有字段不动）。

## ⑤ 既有断言的处理（**改写，不删**）

「一个源只试一次」是**旧语义**，被用户指令**显式推翻** ⇒ 允许改写，**但一条不删、强度只增**：

| 旧断言 | 改写为 |
|---|---|
| 「同一首歌连查两次 → **只发一次**请求」 | 「第一次查完之后，第二次**一个请求都不发**」（记录第一次的请求数做基准） |
| 「失败结果也缓存」 | 同上（第二次零新增请求） |
| 「失败的缓存过期后会重新试」 | 过期后请求数**翻倍**（同样用基准计数） |
