# T99 规格：「集号在中段」的解析 + **同名专辑按作品目录归并**

> 状态：**规格先行**（实现前定稿）。
> 起草：2026-11-16。
> 前置任务：T98（「有声读物」识别 + 按集序排列，v3 改版：用户指位置 + 并发扫描）。
> 起因：T98 v3 **真机复验**（真实 NAS，2026-11-16）抓到**两个真问题**：
> ① 《极品家丁》1333 集**排不了**（集号在标题**中段**）；
> ② 《让青春继续第一季》在 NAS 上被拆成**两张同名专辑** ⇒ 列表出现两条同名，且**第 02 集丢了**。

---

## 零、不变量

1. **曲库 = 当前登录用户自己的 NAS 曲库**，规模与内容**因人而异** ⇒ 一切规模相关的量**运行时算**。
2. **集号规则只加在「实测形态」上**：每条新规则都要有**真实样本**（哪台机、哪个账号、什么形态）支撑，
   并有**单测**钉住；**不许**为了「多支持一点」而放宽形态门槛。
3. **归并只认「同名 + 同作品目录」**：作品目录 = `path` 倒数第 3 段（既有 `workDirOf`）——
   ⚠ 服务端**没有**目录浏览端点 ⇒ 目录只能从 `path` 反推（实测 §2.3）。
4. **「不乱」= 稳定排序 + 同键保原序**：宁可把解析不出集号的排在**后面**，也**不丢、不重**。
5. **服务端行为不写死成契约**：一切结论标注「实测（哪台机、哪个账号、何时）」。
6. 既有测试**一条不许删、断言一条不许弱化**；客户端**不新增 npm 依赖**。

---

## 一、目标与不做

### 目标

- **集号在中段**的标题形态能被解析 ⇒ 《极品家丁》1333 集能按集序排（现在**完全排不了**）；
- NAS 把**一部作品拆成两张同名专辑**时，列表**归并成一条**，详情页**把两边的曲目合并**后按集序排
  ⇒ 《让青春继续第一季》**第 02 集不再丢**。

### 明确不做

- ❌ 不做「按目录浏览」（服务端没有）；
- ❌ 不合并**不同名**的专辑（季/卷各算一部：《让青春继续》第一/二/三季**不该**并成一部）；
- ❌ 不合并**同名但不同作品目录**的专辑（那是**真的两部**作品）；
- ❌ 不改服务端行为；不引新 npm 依赖。

## 二、实测基线（**服务端事实**，2026-11-16，本机 + 该账号）

> 探针：`release/verify/t99-01-probe-group-paths.mjs`（gitignored）；T98 v3 真机复验：
> `release/verify/t98v3-05-realmachine-verify.mjs`。

### 2.1 《极品家丁》：集号在标题**中段**

| 项 | 实测 |
|---|---|
| 专辑 | 《极品家丁》，**1333 集**（服务端 `trackCount = 1333`） |
| 作品目录（`path` 倒数第 3 段） | `极品家丁` |
| 分段目录（倒数第 2 段） | `0000-0200`（后续还有 `0201-0400` 等 ⇒ **同一作品目录**） |
| 标题形态 | `极品家丁 0000预告片`、`极品家丁 0001 公子，公子`、`极品家丁 1332 万千柔情（完结）` |

⇒ ⭐ 集号形态 = **「作品名 + 空格 + 4 位数字 + 标题」**；
⚠ **数字后可以没有空格**（`0000预告片`）⇒ 规则必须兼容两种。

⚠ 现状：现有 7 条规则都要求集号在**开头**（`dash-prefix` / `dotted-prefix` / `bracket` /
`digits-only`）或**结尾纯数字**（`trailing`）⇒ 解析率 **1.1%** ⇒ 形态不一致 ⇒ **不排序**；
而服务端原序是 `createdAt,desc` ⇒ 用户看到的是**倒着**的（`0000预告片` 在最后）。

### 2.2 《让青春继续第一季》：**被拆成两张同名专辑**

| 专辑 | 服务端集数 | 作品目录 | 分段目录 | 标题样例 |
|---|---|---|---|---|
| 《让青春继续第一季》 | **31** | `让青春继续` | `让青春继续第1季(全32集)` | `让青春继续第一季 10` / `01` / `03` |
| 《让青春继续第一季》 | **1** | `让青春继续` | `让青春继续第1季(全32集)` | `让青春继续第一季 02` |

⇒ ⭐ **同名 + 同作品目录 + 同分段目录** ⇒ 确系**同一部作品被服务端拆开**；
⇒ ⚠ 31 集那张**缺第 02 集** ⇒ 用户现在**少看到一集**（这才是要修的实质问题，不只是「两条同名」）；
⇒ 《让青春继续第二季》（6 集）/《第三季》（13 集）**名字不同** ⇒ **不该**被并进来。

### 2.3 作品目录的取法（沿用 T98）

`path` 去掉文件名后取**倒数第 3 段**：
`…/有声小说/禹言/极品家丁/0000-0200/极品家丁 0001 公子，公子.mp3` ⇒ 倒数第 3 段 = `极品家丁`（作品），
倒数第 2 段 = `0000-0200`（分段目录）⇒ 同一作品跨分段目录时**作品目录仍唯一** ✓。

## 三、方案

### 3.1 集号规则：`mid-number`（**放最后**）

```ts
// 标题形态：「作品名 + 空格 + 数字 + 标题」（数字后**可无空格**接文字）
const mid = /^(.+?)\s+(\d{1,5})(?:\s*.*)?$/
```

| 要点 | 取值 | 理由 |
|---|---|---|
| 前缀 | `(.+?)`（≥1 个非空白字符） | 必须**有文字** ⇒ 与 `digits-only`（纯数字）/ `dash-prefix`（数字开头）**不重叠** |
| 分隔 | `\s+` | 作品名与集号之间是**空格**（实测形态） |
| 数字 | `\d{1,5}` | 1–5 位（实测 4 位补零；5 位留给 5 位以上的长篇） |
| 尾巴 | `(?:\s*.*)?$` | 数字后**可无空格**接文字（`0000预告片`）⇒ 也兼容有空格（`1332 万千柔情`） |
| 年份保护 | **不施加** | 与 `digits-only` 同理：2000+ 集的长篇**真实存在**（牧神记 2762 集）⇒ 形态一致性门槛兜底 |
| **优先级** | `EPISODE_RULES` **最后一位** | 最宽松 ⇒ 命中数相同时**不抢**更具体的规则：<br>· `season-episode` / `trailing` 仍能拿到 `[季, 集]`（《让青春继续》）；<br>· `digits-only`（纯数字）不受影响（无前缀文字 ⇒ 不匹配）；<br>· `dash-prefix`（数字开头）不受影响（`(.+?)` 要求前面有文字 ⇒ 数字开头时匹配不到） |

⚠ **形态一致性门槛（≥ 60%）仍然把关**：一条专辑里 60% 的标题能按**同一规则**解析出来才用 ⇒
普通音乐专辑（标题五花八门）不会因为多了这条规则就被排。

### 3.2 归并：**同名 + 同作品目录 ⇒ 一组**

| 组合 | 归并？ | 理由 |
|---|---|---|
| 同名 + **同作品目录** | ✅ 合并 | 服务端把**一部作品**拆开了（实测 §2.2） |
| 同名 + 不同作品目录 | ❌ | 那是**真的两部**作品 |
| 不同名（季/卷） | ❌ | 各算一部（否则三季的集号会混在一起） |

- **归并键** = `专辑名 + 唯一作品目录`（作品目录**不唯一** ⇒ 回落 `albumId` ⇒ 不归并；
  作品目录**缺失** ⇒ 同理不归并 ⇒ **信息不足，宁可分开**）；
- ⚠️ **聚合仍按 `albumId`，归并放在「判定阶段」**（**初稿与实现不一致，按实现修正**）：
  实测存在「**同一张专辑横跨多个作品目录**」⇒ 若把归并键当**聚合**键，
  **一张专辑会被拆成两条**（比不归并更糟）⇒ 聚合**不动**（仍是 `albumId`），
  判定时再按归并键把指标**合并**（集数 / 形态统计 / 均长 / 最长单集累加），
  并按**合并后**的指标打分；
- `AudiobookHit` 新增 **`albumIds`**（组内所有专辑 id，**主专辑** = 集数最多的那个，排第一）；
- ⚠️ **落盘形状不变**（`CandidateSnapshot.dirs` 已含作品目录集合 ⇒ 唯一作品目录**可派生**）
  ⇒ `STATE_VERSION` **不升**（旧落盘**不作废**）；归并是**派生**结果 ⇒ 读回落盘时重算一致。

### 3.3 列表与下钻

- 列表：**一个组一条**（集数 = 组合计）；点进去仍按**主专辑** id 下钻（**路由不变**）；
- **详情页按组拉全量**：主专辑 + 同组其它成员（`/track/album-detail/list` 逐个拉）⇒ 合并 ⇒ 按集序排
  ⇒ 「第 N 集」**跨专辑连续**（第 02 集不再丢）；
- **改判对整组生效**：改判任一成员 ⇒ 整组生效（写 override 时**先清掉组内其它 override**，避免互相打架）。

## 五、验收点

1. **纯函数**（可单测）：
   - `极品家丁 0001 公子，公子` → `1`；`极品家丁 0000预告片` → `0`；`极品家丁 1332 万千柔情（完结）` → `1332`；
   - **不抢**更具体的规则：`让青春继续第一季 10` 仍走 `trailing`（拿 `[季, 集]`）；`0001` 仍走 `digits-only`；
   - 普通音乐标题（`思凡` / `Runaway Mama` / `Untitled`）⇒ 解析为 `null`；
   - 形态一致性：混装专辑（50% 命中）⇒ **不排序**（保持原序）；
2. **归并**：
   - 同名 + 同作品目录 ⇒ **一条**、集数相加（31 + 1 = 32）；
   - 同名 + 不同作品目录 ⇒ **两条**（不合并）；
   - 不同名 ⇒ **两条**（季/卷不合并）；
   - 归并后判定分按**合并后的**数据算；
3. **组级改判**：对组内任一成员「不是有声」⇒ **整组**不再出现在「有声」页；
4. **详情页**：组内两个专辑的曲目**合并**后按集序排 ⇒ 集号**连续**（01…32）⇒ **第 02 集出现**；
5. **E2E**：mock 造两张同名同目录专辑（12 + 1 集）⇒ 列表**一条**、详情 **13 集**且**集序连续**；
6. **回归**：既有单测 / 既有 E2E **一条不许删、断言一条不许弱化**。

## 六、待校准 / 遗留

- ⚠ **归并键用「专辑名」** ⇒ 若服务端把一部作品拆成**两张名字不同**的专辑（如《XXX》/《XXX 完结》），
  仍**不会**被合并（未在实测中遇到 ⇒ 不猜）；
- ⚠ **「作品目录」只取倒数第 3 段** ⇒ 若某部作品的目录深度与别处不同（实测都是
  `有声小说/作者/作品/分段目录/文件`），归并键会不同 ⇒ **未实测的形态不合并**（宁可分开，不误合）；
- ⚠ **组级改判**会让 `localStorage` 的 override 条数变多（按组内成员数）⇒ 量级很小（≤ 几首/组）；
- ⚠ 归并后**集号冲突**（两部作品合并后集号重复）只在「同名 + 同目录」时发生 ⇒ 实测那一组集号连续 ✓；
  若将来出现冲突 ⇒ 排序会按原下标兜底（稳定排序），**不丢不重** ✓。
