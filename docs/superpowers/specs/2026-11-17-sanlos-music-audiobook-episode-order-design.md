# T103 规格：修《极品家丁》14 集掉队（集号规则优先级重排）

> 状态：规格先行（实现前定稿）
> 日期：2026-11-17
> 前置：T99（新增 `mid-number` 规则）、T100（归并键与判定口径）、T101（有声页形态）、T102（封面 id 统一）

---

## 一、问题

《极品家丁》1333 集按集序排列时，**14 集（1.1%）排到了末尾**（掉队）。

界面表现：1333 集里只有 1319 集带「第 N 集」标签，**缺 14 个编号**
（219 / 220 / 268 / 269 / 298 / 299 / 311 / 312 / 330 / 331 / 404 / 405 / 447 / 448）。

实测（2026-11-16，本机 + 该账号，探针 `t99-10`；见 `docs/calibration.md`）：

| 项 | 实测 | 含义 |
|---|---|---|
| 各规则命中数 | `mid-number` **1319** / `bracket` **14** | 掉队的正好是那 14 集 |
| 主序列缺的编号 | 219 / 220 / 268 / 269 / 298 / 299 / 311 / 312 / 330 / 331 / 404 / 405 / 447 / 448 | 1333 集里编号有洞 |
| 掉队 14 集的**中段数字** | **完全相同**（同上 14 个） | 掉队的就是缺的那 14 集，**不是**额外内容 |
| 若让它们用中段数字 | **撞号 0 个**、去重后仍无重复 | 调优先级**不会**引入重复集号 |
| 标题形态 | `极品家丁 0219 夫人的阴谋（1）` | 「（1）/（2）」是**分集后缀**，**不是**集号 |

⇒ 结论：1333 集与编号 0…1332 **一一对应** ⇒ 只要让 `mid-number` 赢过 `bracket` 就能**全部排对**。

---

## 二、根因

`src/api/audiobook.ts` 的 `parseEpisode()` **按代码顺序取第一条命中的规则**，
而 `bracket`（括号数字）排在 `mid-number`（中段数字）**之前**：

- `极品家丁 0219 夫人的阴谋（1）` ⇒ 命中 `bracket` ⇒ 解析成 `[1]`（**错的**，1 是分集后缀）；
- 专辑级 `resolveAlbumEpisodes()` **只用胜出的那一条规则**（此专辑 `mid-number` 1319 : `bracket` 14）
  ⇒ 这 14 集不属于胜出规则 ⇒ 集号 = `null`
  ⇒ `compareEpisode()` 把 `null` 排到**末尾** ⇒ **掉队**。

⇒ 这是**优先级问题**，不是算法问题：规则本身都解析对了，只是**赢错了规则**。

---

## 三、方案（规则优先级重排）

新顺序（`EPISODE_RULES` 的数组顺序与 `parseEpisode()` 的**代码顺序必须完全一致**）：

```
season-episode > episode-cn > dash-prefix > dotted-prefix > digits-only > trailing > mid-number > bracket
```

**改动只有一处**：`bracket` 整块从第 ⑤ 位**降到最末**（第 ⑧ 位）；其余规则**相对顺序不变**
（`digits-only`、`trailing` 各前移一位是被 `bracket` 让出来的，不是主动调整）。

### 三.1 为什么必须这么排（约束推导）

| 约束 | 由来 | 结论 |
|---|---|---|
| `mid-number` 必须赢过 `bracket` | 本任务目标（14 集掉队） | `bracket` 必须在 `mid-number` **之后** |
| `trailing` 必须仍在 `mid-number` **之上** | 既有断言 `parseEpisode('公子，公子 12') ⇒ trailing`（前提未被用户推翻 ⇒ **不许弱化**） | `trailing` 排在 `mid-number` 前 |
| `digits-only` 与 `bracket` **天然互斥** | 纯数字标题不可能含括号字符 | 二者相对顺序**无行为差异** |
| `dash-prefix` / `dotted-prefix` / `season-episode` / `episode-cn` | 都不会被 `mid-number` 命中（数字开头 / 无空白 / 「第 N 集」形态） | 保持最前，**不受影响** |

⇒ 唯一同时满足两条硬约束、且改动最小的排列就是上面这一条。

### 三.2 `bracket` 降为兜底后的语义

`bracket` 的数字出现在标题的**任意位置**（`【01】开篇` / `剧名（1）`）⇒ **位置最松**
⇒ 只有当其它规则都命中不了时才用它。

这与真实数据形态一致：**括号号常常是「分集后缀」而不是集号**
（`夫人的阴谋（1）` / `夫人的阴谋（2）` 共享剧名 `0219` / `0220`）。

### 三.3 副作用（必须写进本规格并用单测钉住）

1. `bracket` 现在会让位给 `trailing`：形如 `剧名（3） 12` 的标题 ⇒ 旧 `bracket`（=3）、新 `trailing`（=12）。
   ⚠ 真实数据里两者几乎不共现（括号号多出现在标题**末尾**）。
2. `bracket` 现在会让位给 `mid-number` —— 这正是本任务要修的那 14 集。
3. `bracket` 在**专辑级平票裁决**（`EPISODE_RULES` 顺序）里也退到最末 ⇒ 命中数相同时不再优先于其它规则。
   ⚠ 仅影响「纯括号号专辑」与其它规则命中数**恰好相等**的情形；纯括号号专辑（`（1）`/`（2）`）仍只有 `bracket` 命中 ⇒ 仍能正常排序。

### 三.4 落盘与兼容性

- 落盘**形状不变**（`ruleCounts` 的键集合不变）⇒ `STATE_VERSION` **仍为 3**、旧落盘可读；
- 重新扫描后 `mid-number` 计数 1319 → 1333、`bracket` 14 → 0
  （旧落盘里的 `bracket: 14` 会留到重扫为止，**无害**：落盘只用来**选规则**，不存每集集号）；
- ⭐ **修复不需要重扫**：详情页 / 秒搜走 `sortTracksByEpisode()` ⇒ **实时解析**标题 ⇒ 新规则立即生效。
