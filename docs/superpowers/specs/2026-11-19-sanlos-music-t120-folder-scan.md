## 一、事实依据（**真机实测**，不是推测）

### 1. 三个新端点（2026-11-19，FN 中继 `https://pure2199.fnos.net/music`，**只打 GET**）

| 端点 | 方法 | 参数 | 实测 |
|---|---|---|---|
| `/app-center/authed-dir/list` | GET | — | `code=0` ⇒ **2 个授权目录** |
| `/app-center/authed-dir/sub/list` | GET | `parent` | `code=0` ⇒ 子目录列表 |
| `/folder-view/list` | GET | `parentPath`（必填）、`sort`（如 `title,asc`） | `code=0` ⇒ 文件夹视图 |

⚠ **`parentPath` 缺了会返回 `code=100002 invalid arguments`**（端点存在，只是缺参）
⇒ **不是** `null` ⇒ 别把它当成「端点不存在」。

### 2. 响应形状（**实测原文**）

```
GET /folder-view/list?parentPath=<目录>&sort=title,asc
⇒ {
    code: 0, msg: "",
    data: {
      folder: {
        name: "有声小说",
        path: "/vol02/1000-0-3d135437/有声小说",
        itemCount: 5244,                 // ← 该目录下（含子目录）的曲目总数
        folders: [ { name, path, itemCount, isAdminDeleted } ],   // ← 一层子目录
        tracks: [ … ]                    // ← **只含「直接挂在这个目录里」的曲目**
      },
      sort: "title,asc"
    }
  }
```

⭐ **`tracks` 只在「直接含文件」的目录里才非空**（实测）：
`/有声小说` ⇒ `tracks=[]`（它下面只有子目录）；
`/有声小说/凝眸七弦伤/赶尸客栈/Disc 01` ⇒ `tracks=76`（这才是文件层）。
⇒ **必须递归**（父目录 → 子目录 → … → 文件层）。

⭐ **`itemCount` 是递归口径**（实测可对账）：
`有声小说=5244` ＝ 子目录之和 `288+89+384+2762+337+1333+51`；
`赶尸客栈=288` ＝ `76+65+69+78`。⇒ 可当「总曲目数」用。

### 3. 真实目录树（实测，本机）

```
/vol02/1000-0-3d135437/            （授权目录 1，itemCount=173670）
├── 有声小说/                       （5244）
│   ├── 凝眸七弦伤/赶尸客栈/Disc 01..04/     （288）
│   ├── 刘慈欣/三体/Disc 01/                 （89）
│   ├── 姬叉/娱乐春秋/001-115 … 346-384/     （384）
│   ├── 宅猪/牧神记/0001-0115 … （25 段）    （2762）
│   ├── 盗墓笔记/ …（337）
│   ├── 禹言/ …（1333）
│   └── 让青春继续/ …（51）
└── （另有 10 个非有声目录：中文音乐 25375、音乐多文件 132777 …）

/vol1/1000/music/music/             （授权目录 2）
```

⭐ **「作品」层 ＝ 文件路径的倒数第 3 段** —— 与客户端现有的
`workDirOf()`（`src/api/audiobook.ts:418`）**完全一致**
（实测 `/有声小说/凝眸七弦伤/赶尸客栈/Disc 01/001- ….mp3` ⇒ 倒数第 3 段 = `赶尸客栈`）。
⇒ **归并键 `workGroupKey(专辑名, 作品目录, 专辑id)` 不用改**。

### 4. 曲目形状（**与客户端现有 `ScanTrack` 逐字对得上**）

`/folder-view/list` 在文件层返回的曲目（实测原文，截断）：

```json
{
  "guid": "0eb3ecd9bc3c47caa823e02f5d51096e",
  "title": "001- 第01季01",
  "coverId": "track_ae09726907a441959d6248978e16fb4b",
  "duration": 829492,                       // ⚠ **毫秒**
  "isCue": false,
  "album": { "guid": "001617d9616b4fd397dd683a06951709",
             "name": "赶尸客栈",
             "coverId": "track_ae09726907a441959d6248978e16fb4b" },
  "artists": [ { "guid": "…", "name": "凝眸七弦伤" } ],
  "audioSpec": { "format": "mp3",
                 "path": "/vol02/1000-0-3d135437/有声小说/凝眸七弦伤/赶尸客栈/Disc 01/001- 第01季01.mp3",
                 "size": 13315623 },
  "isFavorite": false,
  "isAdminDeleted": false
}
```

⇒ 客户端 `toScanTrack()`（`src/api/library.ts:309`）需要的
`id / title / albumId / albumTitle / durationSec / path / coverId / albumCoverId`
**全部有**；`duration` **也是毫秒**（客户端本来就 `÷1000`）⇒ **映射逻辑一字不用改**。

⚠ **两处差异**（要显式处理，不许默认它有）：
- **没有 `trackNo`** ⇒ `trackNo = null` ⇒ 正好是真·有声的常态（客户端本来就只当兜底）；
- **没有 `createdAt`** ⇒ `createdAt = null` ⇒ 只影响全库扫描的「增量水位」，目录扫描用不到。

### 5. 两个必须知道的坑

1. ⚠ **POST `/folder-view/playable-tracks` 的字段更少**（实测：`{guid, title, artists, coverId}`）
   —— **没有 `album`、没有 `duration`、没有 `path`** ⇒ **判不了、归并不了**
   ⇒ **本任务只用 GET**，**不碰**这个 POST 端点（也少一个副作用面）。
2. ⚠ **端点不存在时 body 是 `null`**（不是 `code≠0`）⇒ 老服务端（没更新飞牛）
   ⇒ 调用会失败 ⇒ **必须能回落**（见 §二.2）。

## 二、改法（**换数据源，不换判定**）

### 1. 核心：数据源替换

```
现在：GET /track/list?page=1..87   （17.3 万首全量扫）→ 按 path 关键字过滤 → 聚合
T120：GET /app-center/authed-dir/list          （授权目录根）
      → GET /folder-view/list（目录树 BFS）     （定位「那个文件夹」）
      → GET /folder-view/list（递归到文件层）   （只取那个目录下的曲目）
      → 聚合                                   （**同一个 accumulate()**）
```

⭐ **判定 / 归并 / 卡片 / 下钻 / 改判 / 落盘 —— 一行不改**：
`accumulate()`（`src/state/audiobookStore.ts:424`）吃的就是 `ScanTrack[]`
⇒ 目录浏览喂进来的就是 `ScanTrack[]` ⇒ **同一条管线**。

⚠ **落盘形状不变**（`STATE_VERSION` **不升**）：
旧落盘（v3，全库扫描算出来的 `candidates`）**照样能读** ⇒ 用户升级后
上次扫的结果**直接还在**（不用重扫）⇒ 与 T117 的教训一致（**别让老用户的数据作废**）。

### 2. 回落：**老服务端（没更新飞牛）必须还能用**

```
先试目录浏览 ⇒ 任何一步失败 ⇒ 回落到旧的「全库扫描」⇒ 结果等价（同样的 hits）
```

⚠ 回落必须是**自动**的（用户不该知道服务端版本）⇒ 但**要如实告诉用户**：
页面状态行显示「服务端不支持目录浏览，已改用全库扫描」。

### 3. 界面：文案 ＋ 进度口径

| 位置 | 现在 | T120 |
|---|---|---|
| 提示句 | 「本客户端目前是扫一遍曲库、再按目录名挑出这个文件夹里的作品」 | 「本客户端**按服务端目录浏览**出这个文件夹里的作品」 |
| 扫描中 | 「正在扫描…第 N 页 / 共 M 页（已扫 X 首）」 | 「正在按目录浏览…已取 X 首（走过的目录 N 个）」 |
| 扫完 | 「上次扫描：… · 目录「有声小说」· N 部」 | ＋ **目录绝对路径**（让用户确认到底扫的是哪个目录） |
| 空态 | 「当前曲库里没有识别到有声读物…」 | ⚠ **保持原样**（E2E 断言了它 ⇒ **一个字没动**；只是后半句仍成立） |

⚠ **进度对象加两个字段**（`mode` / `folderPath`）—— 它**不落盘** ⇒ 形状变了也安全。
⚠ **回落提示单独一个字段**（`notice`）—— 塞进 `error` 会显示成「**加载失败**：…」
⇒ **指错方向**的误导 ⇒ 放**状态行**。

### 4. ⚠ **T119 的两条断言必须改写**（**前提被本任务显式推翻**）

T119 钉的是「**客户端还没接**目录接口 ⇒ 旧结论已过时但行为没变」这条**当时为真**的前提。
T120 把这个前提**推翻了** ⇒ 那两条断言**必须改写成新行为的断言**：

| 文件 | 原断言 | T120 改成 |
|---|---|---|
| `test/audiobooks-page.test.tsx` ⑤-c | `expect(hints).toContain('本客户端目前')` | `expect(hints).toContain('按服务端目录浏览')`（**新行为**） |
| `test/t119-doc-claims.test.ts` ① | `expect(readme).toMatch(/本客户端(目前\|还没接\|还没)/)` | `expect(readme).toContain('按服务端目录')`（**新行为**） |

⚠ **其余断言一条不许动**：T119 的 ②③④（页面源码不含旧说法 / 测试文件不含旧说法 /
历史段保持原样）**全部保留** ⇒ 「不许再说『服务端不能浏览目录』」这条纪律**继续有效**。

⚠ **① 实际断言的片段是「按服务端目录」**（**不是**「按服务端目录浏览」）：
README 里这个说法出现在**两处、形状不同** —— `:70` 能力行是「**按服务端目录浏览**出那个文件夹里的作品」
（连续），`:197` 快速开始表是「按**服务端的目录树**浏览」（中间夹了个「的」）
⇒ 断言**只能取两处都有的公共片段**「按服务端目录」⇒ `toContain('按服务端目录')`。
⚠ 用 `toContain`（**片段**）**不是** `toMatch`（正则）—— 这一条**不是**弱化：
被钉住的那句话**从「扫曲库后按目录名挑」变成了「按服务端目录浏览」**。

## 三、钉子（**9 条**，新增 `test/t120-audiobook-folder-scan.test.tsx`）

| # | 钉子 | 抓住谁 |
|---|---|---|
| ① | **目录浏览优先**：新端点可用时 `/track/list` **一次都没被调用** | 「还在全库扫」 |
| ② | **对照组**：新端点返回 `null`（端点不存在）⇒ `/track/list` **被调用** | 「回落失效」 |
| ③ | **定位「那个文件夹」**：按关键字在目录树里找到目标目录 ⇒ 只请求那个目录的子树 | 「还在全库找」 |

| ⑤ | **归并口径一致**：同一张专辑跨多个分段 ⇒ **合成一条** | 「按分段拆成多条」 |
| ⑥ | **判定等价**：同样的曲目 ⇒ 同样的判定分与依据（与旧全库扫描**逐字相同**） | 「判定被改坏」 |
| ⑦ | **时长单位**：`duration` 是毫秒 ⇒ `durationSec` 是秒（1500000 ⇒ 1500） | 「忘了 ÷1000」 |
| ⑧ | **管理员删除的**曲目 / 子目录被跳过（`isAdminDeleted`） | 「把删掉的也算进去」 |
| ⑨ | **落盘兼容**：`STATE_VERSION` **不升** ＋ 旧落盘**照样读得出** | 「老用户数据作废」 |

⚠ **① ② 必须成对**（一个「没发生」类判据**必须有对照组**）：
只钉 ① ⇒ 「这条链路根本没通」也会绿 ⇒ 假绿。

⚠ **⑥ 的形状**：**同一个 mock 曲目集合**，分别走「目录浏览」与「全库扫描」两条路
⇒ 断言 `hits` **逐字相同** ⇒ 这条同时钉住「换了数据源但没换口径」。

⚠ **① 只钉「没走全库扫描」**（**反向判据**），**正向控制交给 ④**（真的取到 12 集）——
① 断言的是「`/track/list` **零次调用**」⇒ 若顺手把「也取到东西」也钉进 ①，
它就会和「**扫不到东西**」的变异同时变红 ⇒ **变异矩阵分不出谁是谁**
⇒ 实测变体 **B（不递归）** 的红集合里**没有** ① ⇒ 才有分辨力。
