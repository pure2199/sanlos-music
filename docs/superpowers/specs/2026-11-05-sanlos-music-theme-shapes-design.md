# T51 设计规格：两套主题的形状适配（圆角令牌化 + 中继提示挪位）

- 日期：2026-11-05
- 承接：T50（品牌名「Sanlos Music」的两套主题适配）
- 状态：已实现并验证

---

## 1. 起因（用户原话）

> 「软件UI不对啊」

用户在 T50 之后打开软件，发现**界面整体不对劲**。本轮**先用真实实例量、后改**，
定位到 4 个确凿的原因（全部实测，见 §2）。

---

## 2. 实测诊断（全部在**真实 userData 的实例**上量出来的）

| # | 问题 | 实测证据 |
| --- | --- | --- |
| **①** | **中继带宽提示把顶栏撑成两行** | `fnm-badge` 被提示撑到 **320px 宽** → 顶栏第一行放不下 → 徽标整块换行 → 顶栏高度 **58px → 141px**，提示文字还自己折成两行 |
| **②** | **行内「收藏 / 下载」按钮两套主题一模一样** | `.fnm-favorite` / `.fnm-download` 的 `border-radius` 实测：apple **6px** / fluent **6px**（写死的，跟主题无关） |
| **③** | **另有 5 处胶囊压根不跟主题走** | `border-radius: 999px` 硬编码在连接徽标、播放条主按钮、详情页返回、全屏页标签页 / 主按钮上 → Windows 11 风下**依然是胶囊** |
| **④** | **词岛在 Windows 11 风下变成方块** | `.fnm-island` 写的是 `var(--radius-pill, 999px)`，而 `--radius-pill` 被主题化成 4px → **屏幕顶部一个白色大矩形**，完全没有「岛」的形状 |

⚠️ **①③ 与 T50 无关**（是公网中继模式暴露出来的既有毛病），**④ 同理**（词岛自己
加载 `tokens.css` 并跟随主题）。T50 只改了品牌名的字号 / 字重 / 字体栈。

⚠️ **但布局本身没坏**：宽 / 窄窗口下顶栏都是 `scrollWidth == clientWidth` → **没有溢出**。
这轮修的是**形状与观感**，不是布局返工。

---

## 3. 决策（用户拍板）

| 决策 | 选择 |
| --- | --- |
| 中继提示怎么处理 | **挪到页面内容区**：一行 12px **灰字**，顶栏恢复 58px 单行 |
| 本轮范围 | **圆角统一 + 中继提示，一起修**（两套主题各自成套） |

---

## 4. 做法

### 4.1 中继提示挪出顶栏

- **新增** `src/components/RelayHint.tsx`：独立组件，链路是 `relay` 才渲染；
  文案仍是「主进程给的 `bandwidthHint` 优先，没有才用兜底文案」（追加要求 H）；
- `src/components/ConnectionBadge.tsx`：**只留触发器**（~69px），不再渲染提示；
- `src/App.tsx`：`<RelayHint />` 渲染在 `.app-shell__main` 顶部
  （`flex: 0 0 auto` + `white-space: nowrap` + `text-overflow: ellipsis`
  → **只占一行**，放不下就截断，绝不把主区撑高）；
- 样式：`.fnm-relayhint` —— 12px、`--text-secondary`（灰）、不占顶栏。

### 4.2 圆角全量令牌化（60 处）

新增 3 个令牌 + 复用已有的：

| 令牌 | Apple 风 | Fluent 风 | 用途 |
| --- | --- | --- | --- |
| `--radius-pill`（已有） | 999px | 4px | 胶囊：徽标、主按钮、标签页、返回 |
| `--radius-panel`（已有） | 10px | 6px | 面板 |
| `--radius-card`（已有） | 10px | 4px | 卡片 |
| `--radius-control`（**新增**） | 6px | 4px | 行内小按钮 |
| `--radius-field`（**新增**） | 8px | 4px | 输入框、提示条 |
| `--radius-sharp`（**新增**） | 4px | 2px | 极小方形图标控件 |

⚠️ **Apple 风的数值 = 原来的硬编码值** → Apple 侧**像素级不变**
（唯一例外：登录页卡片 `12px → 10px`，因为它归 `--radius-card`；2px 差，肉眼不可见）。

⚠️ **`--radius-island`**（新增）：词岛胶囊固定 **999px**，**两套主题同值**
（它不是主题控件）。⚠️ 之所以在 Fluent 组里**也写一遍**，
是因为项目既有约定「两套主题的语义变量集合必须完全相同」
（`test/theme.test.tsx` 钉着，不多不少）→ 少一个令牌就会红。

### 4.3 防回潮的契约测试

新增 `test/theme-radius-css.test.tsx`（8 条）：

1. **`src/**/*.css` 里不再有硬编码圆角**（剥注释后扫，只允许 `var(--radius-*)`）；
2. 圆角令牌**两套主题都齐全**；
3. **两套主题的圆角真的不同**（不是同一套值抄两遍）；
4. **词岛胶囊两套主题都是 999px**（不许在 Fluent 组里写成 4px）；
5. 徽标里**不再有**带宽提示；
6. 提示是主区顶部的一条独立提示（一行、12px、灰字、`flex: 0 0 auto`）；
7. **只有中继链路**才显示提示；
8. 主进程给了 `bandwidthHint` 就用它，没给才用兜底文案。

## 5. 既有断言的处理（**改写，不放宽**）

`test/login-page.test.tsx` 的 4 条 ConnectionBadge 用例**前提被本轮改动推翻**
（提示换了归属组件）→ **改写为新行为断言**：

- 改为**同时渲染徽标与提示组件**（= 真实界面的组合），
  **链路仍由 `bridge.connectionInfo()` 驱动** → 断言链**没有变弱**；
- ⚠️ `test/theme.test.tsx`「两套主题都定义了同一组语义变量（不多不少）」
  → **没有改**：让 `--radius-island` 在 Fluent 组里也定义（同值）来满足它。

## 7. 已知限制（如实标注）

- ⚠️ **登录页卡片**在 Apple 侧由 `12px` 变成 `10px`（归 `--radius-card`）—— 2px 差，肉眼不可见；
- ⚠️ **词岛胶囊仍然偏宽**（~400px × 75px，无歌词时显示「暂无歌词」）——
  那是**词岛窗口的固定尺寸**，**本轮没有动**，要不要收窄待用户拍板；
- ⚠️ **Electron 默认图标**（标题栏左上角小圆球）仍未处理（仓库无 `build/icon.ico`）；
- ⚠️ **未重新打包** → `Sanlos Music.exe` 的**覆盖安装**仍未真机验。
