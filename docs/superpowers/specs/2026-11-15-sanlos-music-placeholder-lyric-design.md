# T93 规格：把「**占位歌词**」视同「没匹配上」

> 一句话：外部源返回的**「此歌曲为纯音乐，请欣赏」**这种占位文本，
> 不该被当成「匹配成功」⇒ 它把链子**卡住**了 ⇒ 内嵌歌词（真对白）**根本没被读**。

---

## 一、现象与根因（**已证**，带实测数据）

### 1.1 现象

- 用户：线上搜不到歌词，**为什么不去读内嵌歌词**？
- 实测被测对象：已安装构建版（`dist/` + `dist-electron/`）+ 真实 NAS。

### 1.2 根因（三条实测证据）

| # | 事实 | 证据 |
|---|---|---|
| ① | **内嵌歌词其实有，而且是真对白** | `readEmbeddedLyric('2299bfd…')` ⇒ **12350 字符 / 265 行 LRC**；头三行 = `[00:00.000]哎呀，行到我对脚都唔知几攰。` / `[00:04.000]金英。你出嚟吉隆坡玩咗几日嘞…` / `[00:10.000]好玩啊，我玩得好开心啊。` |
| ② | **容器读得到标签** | 流头 = `ID3…` ⇒ **MP3（ID3 在文件头 ✓）**；`Range: bytes=0-63` ⇒ `206` + `accept-ranges: bytes` ⇒ 主进程第 ③ 层（读流的前 64 KB）**能**取到标签 |
| ③ | **外部源「命中」的是一句占位** | 源链（网易云→lrclib→QQ→酷狗→酷我→咪咕）跑完，命中的是**咪咕**：`status='ok'`，原文 = **`[00:00.00]此歌曲为纯音乐，请欣赏`**（**21 字符 / 1 行**） |

⇒ **内嵌歌词在链里、也读得到**，但**根本没走到那一步**：
`electron/lyricProvider.ts:1800` 的命中判据是
「`status === 'ok'` **且**原文非空」⇒ 一句 21 字的占位文本**算命中** ⇒
链子**立刻返回** ⇒ 渲染层拿到 `origin='external'` ⇒
**渲染层那条「回落本地（内嵌 → NAS）」的分支根本没被触发**。

### 1.3 为什么「有内嵌却没用上」是**真 bug** 而不是「设计如此」

- 设计上（`src/player/lyricSource.ts:410-418`）：**线上匹配不上 ⇒ 回落内嵌 ⇒ 再回落 NAS**；
- 链子自己的注释也写着：「⚠️ `ok` 但原文与翻译**都为空** ⇒ 视同**匹配不上** ⇒ 回落本地」
  ⇒ **意图**就是「内容太空 ⇒ 视同没匹配上」；
- ⚠️ 只是**判据太松**：只挡「空」，**没挡「占位」** ⇒ 一个 21 字的提示语骗过了整条链。

## 二、目标与**明确不做**的事

### 2.1 目标

1. 外部源返回的**占位文本** ⇒ **视同「没匹配上」** ⇒ 链子**继续试下一个源**；
2. 所有源都是占位 ⇒ 报 `not-found` ⇒ 渲染层**回落内嵌**（真对白）⇒ 再回落 NAS；
3. **不误伤真歌词**：哪怕只有 **1 行**的真歌词，也**不许**被当成占位。

### 2.2 明确**不做**

| 不做 | 理由 |
|---|---|
| 改「线上优先 / 本地优先」的**政策** | T70 用户拍板的是「线上优先」⇒ 本轮**只修判据**，不改政策 |
| 把「线上只有 1 行」也视同没匹配上 | T90-⑨ 已记录「冷门歌可能只有 1 行」是**既有行为** ⇒ 本轮**只挡占位**，不挡「短」 |
| 把 NAS 自带的占位也当成「没有」 | NAS 那句「此歌曲为纯音乐，请欣赏」**有信息量**（告诉用户这歌没词）⇒ 保留 |
| 改内嵌歌词的读取方式（尾读 MP4 的 `moov`） | 与本问题**无关**（这一首是 MP3，头读就够）⇒ 另开一轮 |

## 三、判据设计（「什么算占位」）

### 3.1 规则

```
占位 ⇔ 去掉时间戳后的正文 **长度 ≤ 40** 且 **命中占位特征**
```

### 3.2 占位特征表

| 类别 | 特征（任一命中即可） |
|---|---|
| 中文 | 纯音乐 / 纯音樂 / 纯音 / 请欣赏 / 請欣賞 / 暂无歌词 / 暫無歌詞 / 无歌词 / 無歌詞 / 没有歌词 |
| 英文 | instrumental / music only / no lyrics / no lyric |

### 3.3 为什么这样定（三条自证）

| 顾虑 | 怎么挡住的 |
|---|---|
| 误伤真歌词 | 真歌词**正文很长**（> 40 字）⇒ 一律不判占位 ⇒ 只有**短文本**才可能是占位 |
| 误伤「1 行的真歌词」 | 1 行的真歌词**不含**「纯音乐 / 请欣赏 / instrumental」这类特征 ⇒ 不判占位（T90-⑨ 的 QQ 1 行案例不受影响） |
| 漏判 | 各源措辞不同，但**都指向同一件事**（这歌没词）⇒ 特征表覆盖中英两套常见写法 |

⚠️ **实测样本**：咪咕的 `[00:00.00]此歌曲为纯音乐，请欣赏` ⇒ 去掉时间戳后 21 字 ≤ 40 ⇒
命中「纯音乐」「请欣赏」⇒ **判为占位** ✓。

## 四、改哪两层（**一个判定，两处使用**）

| 层 | 文件 | 改法 |
|---|---|---|
| **判定** | `shared/lyricPlaceholder.ts`（**新增**） | `isPlaceholderLyric(text): boolean` —— **纯函数**、无依赖、可单测 |
| **源链**（主进程） | `electron/lyricProvider.ts` | 命中判据加上「**且不是占位**」⇒ 占位**不算命中** ⇒ 继续试下一个源 |
| **渲染层链** | `src/player/lyricSource.ts` | 「线上结果」多一条判据：原文是占位 ⇒ **视同没匹配上** ⇒ 往内嵌回落（**兜底**：防止任何路径绕过 provider 时又被占位卡住） |

⚠️ **为什么两层都改**：
- provider 层改 ⇒ **占位不会占用「命中」这个位置** ⇒ 链子能继续往下试（这是**主要**修复）；
- 渲染层改 ⇒ **兜底**（缓存里的旧结果 / 未来的新路径）⇒ 两层用**同一个判定**（`shared/`）⇒ 不漂移。

⚠️ `shared/lyricPlaceholder.ts` **不得** import Electron / Node 内置模块 / DOM 类型
（渲染进程在 `contextIsolation: true` 沙箱里）—— 与 `shared/lyricProvider.ts` 同一套规矩。
