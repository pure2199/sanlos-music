# T68 规格：修「真逐字填充整行失效」——`buildSegments` 的词/文本对齐语义不一致

> 日期：2026-11-09
> 前置：T66（歌词对时改进）→ T67（接网易云 yrc 真逐字）
> 状态：规格先行，实现另起一个 commit

---

## ① 起因（用户真机反馈 + 实测定位）

用户反馈：**「对不上」**；并进一步指出**「我感觉是你没走字的时间戳」**。

T67 把网易云 yrc（真逐字）接了进来，并验证过「词数 == 逐字标签数」。但那验证的是
**解析层**；**渲染层**还有一道独立的关卡，T67 的探针没覆盖到。

实测（探针 `release/verify/fnm-probe-word-timestamps-v2.mjs`，真实网易云接口 + 真实生产代码）：

| 判据 | 结果 | 结论 |
| --- | --- | --- |
| ① 词级时间戳是否贯通到 `line.words` | **2076 / 2076 个词的起点能在 yrc 原始词起点集合里精确命中（误差 0）** | ✅ **通的**，不是「没走字的时间戳」 |
| ② 词间隔是否均匀（均分 vs 真逐字） | 每首歌有 **54~100 种**不同间隔，`zeroGap = 0` | ✅ 真逐字，不是按音节均分 |
| ③ 渲染层能否把词与行文本对上 | **260 行里 19 行（7.3%）对不上** | ❌ **这些行整行退化成纯文本、不填色** |

> ⚠️ 一次探针曾报「459 个词时间戳不匹配」，那是**探针自己的顺序对齐假设错了**
> （yrc 的零时长词会被并入前词 ⇒ 顺序错位）。改用**集合匹配**后是 0 不匹配。
> 记录在此，避免后来人重蹈。

## ② 根因：三处语义互相打架（`src/ui/lyrics/LyricView.tsx` 的 `buildSegments`）

```ts
// ① owner 按「词文本的**原始长度**」构建 —— 词文本若含空格，这里就把空格算进去了
for (let index = 0; index < words.length; index += 1) {
  const word = words[index]!
  for (let i = 0; i < word.text.length; i += 1) owner.push(index)
}
// ② 早退判据却拿 owner.length 去比「行文本**去空白后**的长度」—— 两个语义不同的量在比
const stripped = text.replace(/\s+/g, '')
if (owner.length !== stripped.length) return []
// ③ 第二遍循环里：空白字符 `continue`、**不消耗 cursor**
//    ⇒ 实际把 owner 当作「**非空白字符序号**」在用
```

**为什么以前没炸**：T12 的伪逐字里 `words[i].text` 来自 `splitIntoWords`，**永不含空格**
⇒ ①的「原始长度」恰好等于②的「去空白长度」，三处语义碰巧一致 ⇒ bug 隐形。

**为什么现在炸**：T67 的 yrc 词文本**含空格**（英文歌的词间空格；且整行只有**一个**词元组时，
那个「词」= 整行文本 ⇒ 内部空格更多）⇒ ①比②大（差值 = 该行空格数，实测 2~3）
⇒ **早退触发 ⇒ 整行退化成整段纯文本 ⇒ 这一行完全不填色**。

实测样本特征高度一致：`words=1`（整行一个词）、集中在歌曲**开头几行**（`lineTime` 0/1/2/3）、
`ownerLen - strippedLen` 正好等于该行空格数。

---

## ③ 修法（最小、只改一处）

`owner` 改为按 **词文本去空白后**的字符数构建 —— 与②的判据、与③的 cursor 语义**全部对齐**：

```ts
for (let index = 0; index < words.length; index += 1) {
  const word = words[index]!
  const chars = word.text.replace(/\s+/g, '')
  for (let i = 0; i < chars.length; i += 1) owner.push(index)
}
```

**为什么这样就够**：

- ②的判据变成「**词的**非空白字符总数 == **行文本的**非空白字符总数」⇒ 同语义，可比；
- ③的 cursor 语义本来就是「非空白字符序号」⇒ 与 owner 一致 ⇒ **索引不再错位**；
- 词内/词间的空白仍由第二遍循环单独 push 成 `isWord: false` 的片段
  ⇒ **T12 的「拉丁文不显示成 `helloworld`」不变式依然成立**；
- 词文本含内部空格的行（整行一个词）⇒ 拆成多个片段但 **`wordIndex` 全为同一个**
  ⇒ 渲染时它们**一起染色** ⇒ 与 yrc 语义一致（yrc 本就把整行当作一个时间段）。

**保守兜底不变**：仍然对不上时**照样 `return []`**（整行纯文本，不崩、不乱填）——
只是判据从此**比的是同一个东西**，不会再误杀。

## ④ 不变式（钉死）

1. **行级 LRC（伪逐字）路径行为一字不变** —— `splitIntoWords` 产出的词文本永不含空格
   ⇒ 去空白前后长度相同 ⇒ `owner` 与之前**逐位相同** ⇒ 输出片段逐位相同；
2. **既有断言一条不许删、一条不许削弱**（只追加新用例）；
3. **不改**：`src/ui/lyrics/parse.ts`（解析与时间戳语义）、`src/ui/lyrics/doubleLine.ts`
   （`findActiveWord` / `computeLineProgress`，二者已用真实 `word.start/end`，经复核无误）、
   `electron/lyricProvider.ts`（yrc 转换）、`src/island/IslandApp.tsx`（词岛走同一个 `LyricView`）；
4. **不引新 npm 依赖**、**不新增出网端点**、**渲染层不碰网络**；
5. **不改** T66 的输出延迟补偿语义、不改 T67 的 yrc 优先级与回退语义。
