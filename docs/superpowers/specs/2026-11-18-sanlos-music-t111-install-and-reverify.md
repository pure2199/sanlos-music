## 四、真机复验的**判据**（这一节是本轮的关键）

### 4.1 「这首歌有没有歌词」怎么判

**不看 DOM 文本**（会滞后一首 —— 实测切到第 4 首时，窗口里还是第 3 首的「望着你」），
**看歌词窗自己收到的 `lyric:state` 消息**：

```ts
{ kind: 'track', track: { id, title, artist, coverId }, lines: LyricLine[] }
```

- `lines.length > 0` ⇒ **有词**；`lines.length === 0` ⇒ **没词**（线上没匹配上 ＋ 也没有内嵌）。
- 消息**带曲目 id** ⇒ 不会串台、不会滞后 ⇒ 判据是**逐字可判**的。

### 4.2 「窗口在不在屏幕上」怎么判

**问主进程** `BrowserWindow.isVisible()`（**OS 级**）——
窗口被 `hide()` 了，DOM 元素照样报「可见」⇒ DOM 级断言是**假绿**。

### 4.3 T106 的三条断言（顺序有讲究）

| 步 | 动作 | 期望 |
|---|---|---|
| ① | 播**有词**的歌 | 经典窗**被创建**且**可见** |
| ② | 播**没词**的歌（有声读物的一集） | 经典窗**存在但不可见**（证明不是「被干掉」） |
| ③ | 换回**有词**的歌（**全程不碰开关**） | 经典窗**自己回来** |

⇒ 同一套断言在**词岛**形态上再跑一遍（词岛**有词才创建** ⇒ 先「有词」建岛，再「没词」看它收不收）。

### 4.4 T107 的三条断言

| 断言 | 判据 |
|---|---|
| 指定源 ⇒ 真的换了 | 全屏页状态行变成「歌词来源：**QQ 音乐**」 |
| **桌面歌词跟着换** | 经典窗收到**同曲目、歌词首行不同**的新 `lyric:state` |
| 「恢复自动」⇒ 回到全局 | 状态行不再是 QQ 音乐，且又收到一条 track 消息 |

⚠️ 全局源用**酷我**（T108 真机实测：416 ms、ok、带逐字），指定源用 **QQ 音乐**（685 ms、ok、带逐字）
⇒ 两个源在这台机上**都能用** ⇒ 「换源」这件事有真实的鉴别力。

## 五、隔离 userData（不碰用户真实数据）

真机复验**必须**是「真实账号 + 真实 NAS」，但**不能**动用户自己的偏好 / 下载目录：

- `--user-data-dir=<临时目录>` ⇒ 只复制 `session.bin`（DPAPI 加密的会话）＋ `Local State`，
  另写一份 `prefs.json`（桌面歌词**开着**、形态=经典、全局源=酷我 —— 与用户真实偏好同源）。
- ⚠️ `--user-data-dir` 会**触发迁移守卫**（`electron/userDataDir.ts`）⇒
  旧目录**不会被搬走**（`skipped: user-data-dir-redirected`）⇒ 用户真实数据一个字节都不动。
- 跑完**删掉临时目录**。
