# T86 规格：把**签名链路**补上 —— 产物能真的带上签名，且「签没签上」是**构建期事实**

> 状态：**已实施**（规格先行 = 本文件；实现 = 下一个 commit）
> 关联：T85（签名闸的判定口径）、T82（允许安装未签名包）、T23（自动更新本体）
> 触发：用户 2026-11-10 23:20：「你把证书补上，这个你帮我修好」
> （承接 T85 的追问「现在有签名了吗」—— 实测：**没有**，8 个历史安装包全是 `NotSigned`）

## 1. 先划清边界（**必须先说清楚，否则会做出「假信任」**）

### 1.1 我**能**做的

- 生成**本地自签**代码签名证书 ⇒ 让产物**真的带上 Authenticode 签名**；
- 把 electron-builder 接上签名（**不改 `win.sign`**：它原生读 `WIN_CSC_LINK` + `WIN_CSC_KEY_PASSWORD`）；
- 加一道**打包后签名断言** ⇒ 「签没签上、签的是谁」是**构建输出里的一行事实**；
- 用**真包 + 真 PowerShell 探测**把更新链路跑通（此前只跑过 mock）。

### 1.2 我**不能**做的

- ❌ 拿不到**公开可信**的证书：OV/EV 需要**主体材料 + CA 核验（电话/视频）+ 硬件 token/HSM + 付款**，
  这一段只能人走流程；
- ❌ **自签证书不可信**：对外发布时 Windows 仍提示「未知发布者 / 不受信任的证书」。

### 1.3 ⚠️ 为什么不把自签产物发到公开 Release

自签证书让 Windows 显示「发布者：**公司名**」，但**查不到信任链**
⇒ 比不签名**更容易误导人**（看起来像有公司背书，其实没有）。
⇒ **自签产物只用于本地/内部把链路跑通**（用户 2026-11-10 已拍板）。

## 2. 决策（用户 2026-11-10 23:20 拍板）

| 决策点 | 选择 | 理由 |
|---|---|---|
| 证书性质与用途 | **自签先跑通链路**（不进公开 Release） | 我办不了公开可信证书；先把链路与断言做实 |
| 主体名（CN） | **公司法定主体名**「广西闪链时空网络科技有限公司」 | Windows 显示的「发布者」= CN；真实证书**必须**是这个 ⇒ 日后换真证书**不用改任何配置**、用户填的「预期签名者」也不用改 |
| 本机是否导入受信任根 | **导入（仅当前用户）** | 本机实测能看到 `Status=Valid` ⇒ 能完整验「有签名且被信任」那一支；只影响本机，随时可撤销 |

## 3. 实现

### 3.1 工具

| 文件 | 作用 |
|---|---|
| `tools/fn-make-selfsigned-cert.mjs`（新） | 生成自签**代码签名**证书（RSA 3072 / SHA-256 / 3 年），导出 `.pfx` + `.cer` + 口令文件到 `release/certs/`（**gitignored**）；`--trust` 导入**当前用户**「受信任的根证书颁发机构」；**自检**（读回 .pfx 确认私钥在位、主体名一致） |
| `tools/fn-check-signature.mjs`（新） | 读产物的 `Get-AuthenticodeSignature` ⇒ 打印 `Status` / 签名者 / 指纹；按 `--expect signed\|none` / `--expect-signer` / `--pfx` 判定，**不符合就非零退出** |

### 3.2 打包后断言（`scripts/pack.cjs`）

- ⚠️ **为什么不能信「打包成功」**：electron-builder 在签名环节失败时**可能只警告、不失败**；
- ⇒ 配了 `WIN_CSC_LINK`/`CSC_LINK` ⇒ 打包后**主动**查暂存目录（= 本次构建的产物，
  **不是**输出目录 —— 输出目录里可能躺着历史旧包 ⇒ 会误报）；
  **没签上 ⇒ 打包失败**；
- ⇒ 没配证书 ⇒ 打印「产物未签名（预期行为）」，**不**失败（保持现在的默认行为）。

### 3.3 ⚠️ 顺带修掉一个**真缺陷**（`electron/update.ts`）

**症状**：签名者主体名含中文时，客户端读到的签名者与用户填的**永远对不上**
⇒ 带签名的包会被**莫名其妙**地拒掉。

**根因**：PowerShell 往**管道**写 stdout 用的是**控制台代码页**
（简体中文机器 = OEM 936 / GBK），**不是 UTF-8**
⇒ Node 按 UTF-8 解出来是**乱码** ⇒ 与「预期的代码签名者」比对必然不等。
（实测：`CN=广西闪链时空网络科技有限公司` 被读成**一串替换字符与问号**，中文部分**全丢**）

**修法**：让 PowerShell 输出 **base64(UTF-8)**，Node 侧再解 ⇒ **与代码页无关**。
（顺带：PowerShell 脚本改用 `-EncodedCommand` 传参 ——
`-Command "<脚本>"` 会被 Windows 命令行 + PowerShell **二次解析** ⇒ 脚本里的引号被吃掉
⇒ 实测 `$ErrorActionPreference='Stop'` 变成「把 `Stop` 当命令执行」并报错。）

## 4. 验收

1. **产物实测**：`Get-AuthenticodeSignature` ⇒ `Status=Valid`、`SignerCertificate.Subject=CN=广西闪链时空网络科技有限公司`；
2. **更新链路用真包跑通三支**（真 PowerShell 探测，不是 mock）：
   - 预期签名者**一致** ⇒ 放行（`openPath` 被调）；
   - 预期签名者**不符** ⇒ 拒绝（理由含「不符」）；
   - **未填**预期签名者 ⇒ 拒绝（理由含「未配置」）；
3. **打包后断言**：配了证书却没签上 ⇒ **打包失败**（变异自证）；
4. **没配证书时**打包**照旧成功**（原行为一字不变）；
5. tsc / vitest / e2e 全绿。

## 5. 真实证书（OV）采购清单 —— 日后换证书**只改环境变量、不改代码**

| 路线 | 可行性 | 要点 |
|---|---|---|
| **商业 OV**（DigiCert / Sectigo / GlobalSign 等） | ✅ 但要走流程 | 私钥**必须**在硬件 token / HSM / 云签名（软件 `.pfx` 已被行业规则禁掉）；有效期上限已被压到 **459 天**（CA/B Forum 2026-02-23 起）；价格区间约 **$96.75（5 年）~$700（1 年）** |
| **Azure Artifact Signing** | ❌ 对中国大陆主体**不可用** | 公开信任资格限美国 / 加拿大 / 欧盟 / 英国的组织 + 美加个人；组织还需 3 年以上可验证税务历史 |
| **自签** | ⚠️ 只在本机不弹警告 | 对外照样「未知发布者」⇒ 公开发布**零意义** |

⚠️ **主体名口径（一次定死，别换）**：CN **必须**是 CA 核验过的**法律主体名**
（与营业执照 / 注册证明一致）⇒ 软件名只能住在 exe 元数据（`ProductName` / `copyright`）里。
⇒ Windows 上显示的「发布者」= 证书 CN = **公司名**，**不是**软件名。
⇒ **换证书 = 换显示名 + SmartScreen 信誉清零**。
⚠️ **签名 ≠ 不弹窗**：SmartScreen 判的是**文件哈希的信誉** ⇒ 第一版照样弹；
要靠真实下载量 + 干净安装积累（通常数周、数百次）；**每次重新打包哈希就变 ⇒ 信誉清零**；
**必须加时间戳**（否则证书到期后历史安装包全部验证失败）。
唯一彻底免的是 **Microsoft Store**（商店代签，显示商店名）。

## 6. 不做的事

- ❌ 不把自签产物发到公开 Release（见 §1.3）；
- ❌ 不改 `electron-builder.yml` 的 `win.sign`（留空 = 默认不签；签不签由环境变量决定）；
- ❌ 不把 `.pfx` / 口令**入库**（`release/certs/` 整个目录是 gitignored）；
- ❌ 不改客户端的判定口径（那是 T85 已经定好的矩阵，一字不动）。
