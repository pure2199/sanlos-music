# T89-③：自动更新的临时安装包目录 —— 旧安装包不清理

> 日期：2026-11-12
> 状态：设计已定，待实现
> 关联任务：T89-③（用户指令「1.2.3.4.6 都做」的第 3 项）

---

## 一、问题

自动更新把安装包下载到：

```
%TEMP%\fnmusic-update\FN-Music-Setup-<版本>.exe
```

⚠️ **这个目录只进不出**：

- 每更新一版就多一个 **86 MB** 的安装包（实测 v0.2.5 的 Setup = 86,106,756 B），
  旧的那份**永远留在 `%TEMP%`**；
- 下载中断留下的 `.part` 碎片也留着；
- **本机实测残留**：`%TEMP%\fnmusic-update\FN-Music-Setup-9.9.9.exe`（33 字节）。

⚠️ 那 33 字节的残留**不是用户下载的**，是 **E2E 造的**：E2E 里那条
「自动更新：检查到新版本 → 下载校验通过 → 签名不过就不许安装」用例会真的下载一次
（下载是这条用例的被测对象），而 mock 的清单版本是 `9.9.9`。

⚠️⚠️ **更麻烦的一点**：E2E 只隔离了 `--user-data-dir`（userData），
**没有隔离 `%TEMP%`** ⇒ E2E 与真实应用**共用**同一个更新目录。

---

## 二、两个必须一起解决的问题

| # | 问题 | 后果 |
|---|---|---|
| **A** | 应用**不清理**旧安装包 | `%TEMP%` 里越堆越多（一次更新 +86 MB） |
| **B** | E2E **污染真实 `%TEMP%`** | 每次跑 E2E 都在用户机器上留一个假安装包 |

⚠️ **B 不是 A 的附属品，而是 A 的放大器**：只要 A 加了「启动时清空更新目录」，
E2E 每次启动应用都会**清掉用户真实待装的安装包** ⇒ **必须先把 B 修掉**。

---

## 三、方案

### 3.1 关键事实：「下载状态」是**内存态** ⇒ 跨会话的残留一定是垃圾

`src/state/updateStore.ts` 的 `download` / `status` **只存在内存里**（Zustand，不落盘）：

```ts
if (!download || download.status !== 'ok') {
  set({ status: 'error', error: '还没有已下载的安装包' })
  return
}
```

⇒ **重启应用后，「启动安装」必然报「还没有已下载的安装包」** ⇒
「下载了、关掉应用、明天再装」这个流程**本来就不存在**。

⇒ **结论**：应用启动时还躺在更新目录里的文件，**按定义就是垃圾** ⇒ 可以放心清空。
（这不是「顺手清理」，是「把上一轮会话的残留清掉」。）

### 3.2 两条清理规则

| 时机 | 规则 | 为什么 |
|---|---|---|
| **应用启动** | 清空更新目录里的**所有文件** | 上一轮会话的残留（下载状态已随进程消失 ⇒ 用不上了） |
| **下载成功后** | 只保留**本次下载的文件**，其余全删 | 同一会话里连下两版 ⇒ 别占着两份 86 MB；顺带清掉 `.part` 碎片 |

⚠️ **下载失败时不动任何文件** ⇒ 失败不会把用户已有的那份弄丢。

⚠️ **删不掉就算了**（文件被安装器占用 / 权限不足）⇒ 清理**绝不能**让启动或下载失败。

### 3.3 更新目录可被环境变量改写（**为了隔离**）

```
FNM_UPDATE_DIR=<目录>   ⇒  用它，替代 %TEMP%\fnmusic-update
```

- ⚠️ **只在主进程读**（渲染层永远不碰）⇒ 不违反「渲染层不碰文件系统」。
- 默认值**不变**：`%TEMP%\fnmusic-update`（安装包放临时目录是对的：
  系统会清理，且不该进 `%APPDATA%` 漫游配置）。
- **E2E 用它** ⇒ E2E 的更新目录是临时目录 ⇒ **不再碰用户真实 `%TEMP%`**，
  也不会清掉用户待装的安装包。
- 名字沿用仓库既有风格（`FNM_PACK_OUTPUT`）。

### 3.4 只删**普通文件**，不删目录

更新目录里理论上只有文件。遇到子目录 ⇒ **跳过**（不递归、不删目录）
⇒ 清理永远不会误伤别的东西。

## 五、验收点

1. `tsc --noEmit` exit 0；`vitest` 全绿（既有测试一条不许删、断言一条不许削弱）。
2. 新增单测覆盖：
   - 清空时**只删普通文件**，子目录**原样留着**；
   - `keep` 指定的文件**不被删**；
   - 删不掉的文件**不影响其它文件被删**，也不抛错；
   - 目录不存在 ⇒ 不报错（返回空结果）。
3. E2E：**34 条仍全绿**，且跑完后 `%TEMP%\fnmusic-update` **不再新增文件**。
4. 真机：启动一次 v0.2.6 ⇒ 旧的 `FN-Music-Setup-9.9.9.exe` 残留**被清掉**。

---

## 六、明确不做

- 不删 `%TEMP%` 里的**其它**东西（只管自己那个子目录）；
- 不把安装包搬进 `%APPDATA%`（漫游配置里塞 86 MB 是坏习惯）；
- 不给清理失败加「重试三次」之类的花活（清不掉就留着，下次启动再清）；
- 不在渲染层做任何清理（渲染层不碰文件系统）。
