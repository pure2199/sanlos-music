## 五、验收点

| # | 验收项 | 怎么验 |
|---|---|---|
| 1 | `docs/releases/v0.2.8.md` 能被 CI 当作 Release 正文 | 路径必须是 `docs/releases/<tag>.md`（`release.yml` 读 `docs/releases/$env:TAG.md`，找不到就 **throw**）⇒ 文件名必须是 `v0.2.8.md` |
| 2 | 发布说明是 **LF**、**UTF-8 无 BOM** | 字节自检：`crlf=0`、无 BOM、无 U+FFFD |
| 3 | changelog 仍是 **CRLF**、纯插入 | `git diff --numstat` 期望 `+N / -1`（那 1 行是「当前版本」）；`crlf` 计数与改动前一致、`lf=0` |
| 4 | 每个数字都能指到一条实测 | 对照 §3.2 的出处表逐条核 |
| 5 | 没有未实测的断言 | 通读一遍：凡是「已修好 / 全部达标」类的话，必须有对应数字 |
| 6 | 不出现「假陈述」 | 签名状态写成**当前事实**（仍未签名）；校验值**不写死数字**（CI 追加） |
| 7 | 两个 commit、顺序正确 | `git log --oneline -2` ⇒ 规格在前、实现在后 |
