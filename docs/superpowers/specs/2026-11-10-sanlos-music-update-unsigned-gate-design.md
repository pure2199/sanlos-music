# T85 规格：修好自动更新的签名闸 —— 让「允许安装未签名的更新包」**真的生效**

> 状态：**已实施**（规格先行 = 本文件；实现 = 下一个 commit）
> 关联：T82（允许安装未签名包）、T23（自动更新本体）、v0.2.3 发版
> 触发：v0.2.3 发布后用户问「为什么签名没通过」⇒ 定位到**真缺口**：
> 「允许安装未签名的更新包」这个开关**在代码里是一条死路**，勾了也没用。

## 1. 问题（实测出来的，**不是推测**）

### 1.1 现象

用户在设置页勾上「允许安装未签名的更新包」⇒ 点「启动安装」⇒ 被拒：

```
安装包签名校验未通过，已拒绝启动：未配置「预期的代码签名者」→ 不允许启动安装器
（自动更新等于远程代码执行，这道闸不能省）
```

### 1.2 实测矩阵（真实安装包 + 真实 PowerShell 探测 + `openPath` 打桩）

| # | `expectedSigner` | `allowUnsigned` | 实际结果 |
|---|---|---|---|
| ① | `""`（空） | `true` | ❌ 被拒（**这就是 bug**：用户明明授权了） |
| ② | `"Sanlos Music"` | `true` | ✅ `status=ok`，安装器**真的启动了** |
| ③ | `"Sanlos Music"` | `false` | ❌ 被拒（正确） |

⇒ **只有「预期签名者非空」时，第 ② 行才成立** ⇒ 这个开关**依赖**了一个与它无关的设置。

### 1.3 根因一：主进程**根本不探测**文件（`electron/update.ts`）

`verifyAuthenticode()` 在 `expectedSigner` 为空时**提前返回**：

```ts
const expected = (expectedSigner ?? '').trim()
if (expected === '') {
  return { ok: false, status: 'NotChecked', signer: null, reason: '未配置「预期的代码签名者」→ …' }
}
```

⇒ **没有调用探测执行器** ⇒ 主进程永远不知道这个包到底有没有签名。

而「未签名放行」那道闸（`verifyUnsignedAllowed()`）的第一条是：

```ts
if (signature.status !== 'NotSigned') return { ok: false, reason: signature.reason ?? '未知原因' }
```

⇒ 主进程给的是 `'NotChecked'` ⇒ **第一条永不成立** ⇒ 「允许安装未签名包」这条路**从来没有被走到过**。

### 1.4 根因二：渲染层还有**两道**独立拦截

| 位置 | 拦截逻辑 | 后果 |
|---|---|---|
| `src/state/updateStore.ts:248` | `expectedSigner.trim() === ''` ⇒ 直接 `set({status:'error'})` 并 return | 根本不调主进程 |
| `src/components/SettingsPanel.tsx:360` | `signatureOk = … || (allowUnsignedDraft && signature.status === 'NotSigned')` | 主进程给 `'NotChecked'` ⇒ 按钮 **disabled** ⇒ 用户连点都点不到 |

⇒ 三道拦截**各自**看起来合理，**叠在一起** ⇒ 授权开关彻底失效。

### 1.5 附带发现：设置页文案**自相矛盾**

- `:826-827`：「安装包必须带代码签名，且签名者与「预期的代码签名者」一致才会被启动；**未配置预期签名者时只允许下载，不允许安装**。」
- `:829-831`：「⚠️ 本项目暂未办理代码签名证书 ⇒ 安装包**没有签名**。勾选「允许安装未签名的更新包」**后才允许安装**。」

⇒ 两段话描述的是**互相排斥**的两条规则 ⇒ 用户照着第二段做，结果被第一段拦。

### 1.6 附带发现：测试**从来没测过**「expected 为空 + 已授权」

`test/update.test.ts` 里所有 T82 用例的 `expectedSigner` 都**非空**（`'CN=预期的人'`）
⇒ 「expected 为空」这个分支**只有一条**测试钉住「不许启动」，
**没有任何一条**测「expected 为空 + allowUnsigned 开着」⇒ 死路一直没人发现。

## 2. 决策

> **`allowUnsigned` 与 `expectedSigner` 解耦。**

理由：

1. 这个开关的字面语义是「允许安装**未签名**的更新包」⇒ 它管的是「**这个包有没有签名**」，
   而「预期签名者」管的是「**有签名的话，是谁签的**」⇒ 两件事，本来就不该互相依赖。
2. 本项目**暂未办理代码签名证书**（用户 2026-11-10 拍板）⇒ 产物**必然**是 `NotSigned`
   ⇒ 旧口径等于「这个开关永远没用」。
3. **不放宽**「有签名但签名者不符」那一档：那个包**有**签名，不属于「未签名包」，
   授权对它**无效**（T82 原有语义一字不变）。

## 3. 行为规范（**唯一判定口径**）

### 3.1 判定表

| 安装包 | `expectedSigner` | `allowUnsigned` | SHA-512 | 结果 |
|---|---|---|---|---|
| 无签名（`NotSigned`） | 空 / 任意 | **开** | 相符 | ✅ **放行**（本次修复的核心） |
| 无签名 | 空 / 任意 | 关 | 任意 | ❌ 拒绝（默认行为**不变**） |
| 无签名 | 任意 | 开 | **不符** | ❌ 拒绝（哈希是硬闸，授权救不了） |
| 无签名 | 任意 | 开 | **无从核对** | ❌ 拒绝（同上） |
| **有签名** | 与实际一致 | 任意 | 任意 | ✅ 放行 |
| **有签名** | **空** | 开 | 任意 | ❌ 拒绝（这开关只管「未签名」的包） |
| **有签名** | 与实际**不符** | 开 | 相符 | ❌ 拒绝（授权**也**救不了） |
| 探测失败（`UnknownError` / `Unavailable`） | 任意 | 开 | 任意 | ❌ 拒绝（**不猜**） |

### 3.2 「一份口径」的落地方式

判定逻辑写在 **`shared/update.ts`** 的 `evaluateSignatureGate()` 里，
**主进程与渲染层共用同一个函数** ⇒ 两边不可能再各判各的（这正是本次事故的成因）。

⚠️ **它只判「签名这一关」**；**SHA-512 复核**只有主进程能做（渲染层碰不到文件系统），
留在主进程 `verifyUnsignedAllowed()` 里。

### 3.3 各层的职责

| 层 | 职责 |
|---|---|
| 主进程 `verifyAuthenticode()` | **无条件探测**文件，按探测结果分流（`NotSigned` / 有签名但没配预期 / 签名者不符 / 一致） |
| 主进程 `verifyUnsignedAllowed()` | 「签名这一关」用共享口径 + **SHA-512 硬闸**复核 |
| 渲染层 `updateStore.installUpdate()` | **提前说清楚**（不是闸）：用共享口径判断「点下去会不会被主进程拒」 |
| 渲染层 `SettingsPanel` | 按钮启用条件 = 共享口径；文案与口径**一致** |

⚠️ **渲染层那道「提前拦截」必须与主进程同口径** ——
比主进程**严**就会像这次一样把功能堵死；比主进程**松**则只是多点一次、最终由主进程拒（无害）。

| 位置 | 原断言 | 新断言 | 说明 |
|---|---|---|---|
| `test/update.test.ts:382-392` | 「没配预期签名者 → `status='NotChecked'`、reason 含『未配置』」 | 拆成两条：①「没配预期签名者 + 包**有签名** → 不通过、`reason` 含『未配置』」（**原鉴别力原样补回**）；②「没配预期签名者 + 包**没签名** → **照样探测**、`status='NotSigned'`」 | 前提被**显式推翻**（§2）⇒ 按规矩改写并注明 |
| `test/update.test.ts`（新增） | — | 「没配预期签名者 + 未签名 + **未授权** → 拒绝启动（`openPath` 一次都不许被调）」 | 原鉴别力（「不许启动」）落到**矩阵**里 |

## 5. 验收

1. **矩阵契约测试**（主进程 `verifyAuthenticode` × `launchInstaller`、渲染层 store、设置页）
   ⇒ §3.1 每一行都有对应用例；**既有测试一条不删、断言一条不弱**。
2. **变异自证**（改坏必红）：
   - ① `expected` 为空时提前 return 不探测；
   - ② 去掉 `status !== 'NotSigned'` 那道闸；
   - ③ 渲染层提前拦截不改成同口径；
   - ④ 设置页用**草稿值**而不是**已保存值**。
3. **真机复验**（用户侧）：勾「允许安装未签名的更新包」→ 保存 → 检查 → 下载 → 启动安装
   ⇒ 安装器**真的起来**（此前必然失败）。

## 6. 不做的事

- **不**办理代码签名证书（用户 2026-11-10 拍板：暂不办理）。
- **不**放宽任何其它闸：同源校验、SHA-512 硬闸、路径二次确认、签名者比对**一字不改**。
- **不**改 `electron-builder.yml` 的 `win.sign`（留空 = 不签名；证书到手时不必改代码）。
