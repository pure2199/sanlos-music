# T109、`SongList` 的「可视区高度」在**列表初始为空**时量不到（修复设计）

> 日期：2026-11-18
> 起因：T104 规格 §六「**遗留缺陷（本任务不修，另开编号）**」第 ① 条，
> 以及 T104 / T106 / T107 / T108 台账**顺延**下来的同一条。
> 状态：**设计已定 ⇒ 待实现**。

---

## 一、起因与定性

T104（详情页滚动修复）在规格 §五 记录了一个当时没解释清楚的现象：

> 修好之后这些断言会**假红** —— 而且**随导航路径变化**：有时 10 行、有时 12 行。

当时归因为「虚拟裁剪真正生效后 DOM 里只有一屏 + 缓冲行」，**但那不是根因** ——
「一屏」本身该是**几行**，取决于**真实视口高度**，而真实视口高度**从来没被量到过**。

本任务把它挖到底并修掉。

---

## 二、根因（读码确认，**不是推测**）

### 2.1 事实链

| 环节 | 事实（`src/components/SongList.tsx`） |
|---|---|
| 量高 effect | L202–215：`useEffect(() => { const element = viewportRef.current; if (!element) return; … }, [])` |
| 依赖 | **`[]`** ⇒ 只在**挂载时**跑一次 |
| 视口节点 | `ref={viewportRef}` 只挂在 `.fnm-songlist__viewport` 上（L394） |
| 空态分支 | L377–384：`if (songs.length === 0) return (…)` ⇒ **提前 return** ⇒ **根本不渲染视口节点** |
| 兜底 | L228–230：`measuredHeight > 0 ? measuredHeight : SONG_LIST_FALLBACK_VIEWPORT_HEIGHT`（**600**） |

### 2.2 因果链

1. 曲库 / 搜索 / 详情 / 歌单 / 收藏 / 历史 / 本地音乐 / 随机歌单**全部是异步加载**
   ⇒ `SongList` **挂载那一刻 `songs` 是空的**；
2. ⇒ 走空态分支 ⇒ **视口节点不存在** ⇒ 挂载时 `viewportRef.current === null`
   ⇒ 量高 effect **第一行就 return**（连 `measure()` 都没跑到，更没挂上 `ResizeObserver`）；
3. ⇒ 数据到达 ⇒ 视口节点挂上 ⇒ **但 effect 的依赖是 `[]` ⇒ 不会重跑**；
4. ⇒ `measuredHeight` **永远停在 0** ⇒ 一直用兜底常量 **600**。

### 2.3 后果

| 项 | 缺陷态（兜底 600） | 应有（真实视口，实机约 240px） |
|---|---|---|
| 虚拟窗口可见行数 | `ceil(600 / 48)` = **13** | `ceil(240 / 48)` = **5** |
| DOM 行数 | 18（可见 13 ＋ 缓冲 5） | 10（可见 5 ＋ 缓冲 5） |
| 「滚到底 ⇒ 续一页」的阈值 | 按 600 算 ⇒ **提前触发** `onLoadMore` | 按真实高度算 |
| 「内容填不满可视区 ⇒ 自动续一页」 | 按 600 算 ⇒ 真实视口更矮时**误判为已填满** ⇒ **不续页** ⇒ 首屏少一页 | 正确 |

⭐ **最要命的一条**：**DOM 行数随导航路径摇摆** ——
「初始就有数据」的路径量得到真实高度（8 行），「初始为空」的路径用兜底（18 行）
⇒ 同一份代码、同一类列表，**渲染几行取决于数据什么时候到** ⇒
「DOM 里有 N 行」这种断言**没法写**（T104 因此把 6 处 `toHaveCount` 改成了「滚着收齐」）。

## 三、方案

### 3.1 改法（**一行依赖**）

把量高 effect 的依赖从 `[]` 改成 **`[songs.length]`**。

> 「`songs.length`」= 「**视口是否已渲染**」的信号：
> `songs.length === 0` ⇒ 空态 ⇒ 没有视口；`songs.length > 0` ⇒ 视口已渲染。
> 依赖它 ⇒ 空态→有数据的**那一刻** effect 会重跑 ⇒ 这时 `viewportRef.current` 有值
> ⇒ 量到高度 + 挂上 `ResizeObserver` ⇒ **后续窗口缩放仍能跟随**。

### 3.2 为什么是这个改法（**仓库里已有两个先例**）

| 先例 | 做法 | 结论 |
|---|---|---|
| `src/components/Cards.tsx`（`CardGrid`） | 视口**始终渲染**（空态在视口内部，L382–384）⇒ 挂载即有节点 ⇒ `[]` 依赖成立 | ✅ 结构上无此缺陷 |
| `src/ui/lyrics/LyricView.tsx`（T46 补丁②，L252–273） | 量高 effect 依赖 **`safeLines.length`**，注释明写「**依赖里必须有内容长度**（歌词到达后不会重跑 → `viewportHeight` 永远停在 0）」 | ✅ **同一个坑、同一个修法** |
| `src/components/SongList.tsx` | 依赖 `[]` ＋ 空态提前 return ⇒ 节点后挂载 | ❌ **唯一漏网的一个** |

⇒ 选 `LyricView` 的修法：**改动最小、语义最贴、仓库里已有先例与注释口径**。

### 3.3 为什么不选另外两条路

| 备选 | 否决理由 |
|---|---|
| **让视口始终渲染**（像 `CardGrid`） | 要改**渲染结构**（空态标签进视口）⇒ 动 CSS 布局与 a11y 语义（`role="listbox"` 里塞 `<p>`）⇒ 影响面远大于一行依赖 |
| **改用 callback ref**（节点挂上就量） | 更"根本"，但要同时保留 `viewportRef` 给 `scrollRowIntoView` 用（要维护两个引用 + 观察者生命周期）⇒ 代码量与出错面都变大，**收益相同** |

### 3.4 口径（**不变的部分**）

- **兜底常量 600 不动**（jsdom 量不到高度时仍要用；真机量到值时钳位逻辑照旧）；
- **`clampViewportHeight` 钳位不动**（量到的值钳到窗口高度，防「被内容顶开」的老毛病）；
- **空态渲染结构不动**（仍是 `.fnm-songlist__empty` + `.fnm-songlist__status`，在 `.fnm-songlist` 下）；
- **`CardGrid` / `LyricView` 一行不动**；
- **缓存键、接口、IPC、样式表一律不动**。

## 六、测试怎么钉（**先写红**）

### 6.1 单测（jsdom）

jsdom **没有布局引擎** ⇒ `getBoundingClientRect()` 恒返回 0 ⇒ 量不到高度 ⇒ **正好用来做对照**：

- 把 `HTMLElement.prototype.getBoundingClientRect` mock 成高度 **240**；
- 先渲染 **空列表**（⇒ 无视口节点）→ 再 `rerender` 成 1000 首歌；
- 断言 DOM 行数 == `ceil(240 / 48) + 5` = **10**；
  ⚠ 缺陷态是 `ceil(600 / 48) + 5` = **18** ⇒ **红**；
- 再加一条「初始就有数据 ⇒ 也按实测高度裁剪」（基线：修复前后都绿）。

### 6.2 E2E（真实 Electron）

- 用 mock 曲库里的「**多集专辑示例**」（**40 集**，T104 已用）⇒ 列表够长，虚拟裁剪才显形；
- 在页面里读 `.fnm-songlist__viewport` 的**真实** `getBoundingClientRect().height`；
- 断言 DOM 行数 == `min(真实高度, 窗口高度) → ceil(高度 / 48) + 缓冲 5`（再 `min` 总数）；
- ⚠ 缺陷态恒为 **18**（兜底 600）⇒ 与真实高度算出来的期望**不一致** ⇒ **红**；
- 同时断言 `行数 < 40` ⇒ 虚拟裁剪**确实生效**（不是「全量铺开」蒙对）。
